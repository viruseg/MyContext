# MyContext — дизайн библиотеки контекстных меню

- Дата: 2026-09-27
- Статус: утверждён
- Источник: ТЗ заказчика (пункты 1–5) и 12 развилок, решённых в ходе мозгового штурма

## 1. Цель

Клиентская библиотека на чистом JavaScript (ES2026, ноль рантайм-зависимостей) для создания кастомных контекстных меню, полным визуальным и функциональным аналогом нативных системных меню: неограниченная вложенность подменю, адаптивное позиционирование в пределах экрана, системные анимации, доступность, иконки трёх типов.

## 2. Ограничения

- Рантайм-зависимостей нет вообще: поле `dependencies` в `package.json` отсутствует. Только `devDependencies` для тестов и проверки типов.
- Чистый ES-модуль, импортируется в современных браузерах без транспиляции.
- Библиотека не является глобальным перехватчиком: вне привязанного контейнера она не подавляет и не создаёт меню.
- Работа ведётся напрямую в текущей основной ветке репозитория (`master`), без feature-веток и worktree.

## 4. Архитектура

Один публичный класс, одна точка входа и восемь внутренних модулей. Границы проведены так, чтобы каждый файл можно было понять и протестировать отдельно.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `src/index.js` | Публичная точка входа, реэкспорт `MyContext` | `MyContext.js` |
| `src/MyContext.js` | Оркестратор: приватное состояние, публичный API, жизненный цикл | renderer, layer, hoverIntent, keyboard, theme, positioner |
| `src/positioner.js` | Чистая геометрия: `calculateMenuPosition`, `calculateSubmenuPosition`. Ноль DOM | — |
| `src/renderer.js` | Строит DOM уровня и пункта: сетка, колонки, разделители, шевроны | icons |
| `src/icons.js` | `renderIcon()` → `HTMLElement`. Три типа иконок + санитизация SVG | — |
| `src/layer.js` | Top Layer: создание, показ, скрытие, замер, отложенное скрытие | renderer, positioner |
| `src/hoverIntent.js` | Безопасная область и таймер. Только геометрия прямоугольника | — |
| `src/keyboard.js` | Роуминг-фокус, клавиши, синхронизация ARIA | — |
| `src/theme.js` | Тема и длительность анимации → CSS-переменные и `data-vc-theme` | — |
| `src/constants.js` | Числовые константы и значения опций по умолчанию | — |

Принцип декомпозиции: `positioner.js` и `hoverIntent.js` — чистые функции без побочных эффектов. Всё, что может сломаться геометрически, проверяется без браузера. Браузер нужен только для `layer.js`, `renderer.js` и сквозных сценариев.


## 5. Публичный API

```javascript
new MyContext(items, options)
```

- `attach(domElement)` — навесить слушатель `contextmenu` на контейнер.
- `detach()` — снять слушатель, ничего не разрушая.
- `open({ x, y })` — программное открытие в произвольных координатах.
- `close()` — закрыть все открытые уровни.
- `destroy()` — полная очистка. Идемпотентен.

### 5.1. Типы данных

```javascript
/** @typedef {{ type: 'emoji', value: string }} EmojiIconConfig */
/** @typedef {{ type: 'svg', value: string }} SvgIconConfig */
/** @typedef {{ type: 'raster', value: string, alt: string }} RasterIconConfig */
/** @typedef {EmojiIconConfig | SvgIconConfig | RasterIconConfig} IconConfig */

/**
 * @typedef {object} MenuItem
 * @property {string} [id]
 * @property {string} label
 * @property {IconConfig} [icon]
 * @property {boolean} [disabled]
 * @property {(event: MouseEvent | KeyboardEvent) => void} [action]
 * @property {MenuItem[]} [submenu]
 */

/**
 * @typedef {object} SeparatorItem
 * @property {'separator'} type
 */

/**
 * @typedef {object} MyContextOptions
 * @property {'auto' | 'light' | 'dark'} [theme]  По умолчанию 'auto'
 * @property {number} [animationDuration]          Мс, по умолчанию 140
 * @property {string} [label]                      Доступное имя меню → aria-label
 */
```

`label` добавлен сверх исходного ТЗ: `role="menu"` без доступного имени — дефект доступности, который не пройдёт аудит. Поле опционально, но без него ответственность за имя лежит на пользователе.

## 6. Жизненный цикл

### 6.1. Открытие

`attach(el)` добавляет один слушатель `contextmenu`. Обработчик вызывает `preventDefault()`, сохраняет `{x, y}` и передаёт их в `open()`.

`open({x, y})` на закрытом меню показывает корневой уровень синхронно. На открытом — проходит полный цикл: уровни цепочки гаснут на месте, в Top Layer, и через `animationDuration` корневой показывается в новой точке. Уровень и его пункты при этом не пересоздаются, то есть повторный вызов не заводит второго меню. Под `prefers-reduced-motion: reduce` отложенность пропускается целиком, и цикл проходит за один такт.

Показ корневого уровня:

1. Ленивое построение DOM корневого уровня, если он ещё не создан.
2. Подключение элемента в конец `<body>` под маской замера (см. 7.3, 7.4) и чтение фактических габаритов.
3. `calculateMenuPosition` → `left`, `top` в CSS-пикселях.
4. Снятие маски замера, запись координат, снятие отметки закрытия, `showPopover()`.
5. Регистрация уровня в движке с фокусом: `focus({preventScroll: true})` на элемент уровня, а не на пункт. Выделения после открытия нет (см. 9.1), и первой же стрелкой даётся крайний доступный пункт.

Переоткрытие отменяет висящий показ и начинает цикл заново. «Меню открыто» при этом значит «цепочка непуста **или** показ отложен», и этот ответ снимается до снятия отложенного показа: висящий показ и сам по себе признак открытости, и проверка после снятия сочла бы меню закрытым — третий клик подряд прошёл бы мимо цикла. `close()` и `destroy()` отложенный показ отменяют, иначе `Escape` в окне закрытия воскресил бы меню.

### 6.2. Открытие подменю

Наведение на пункт с `submenu` → `hoverIntent` признаёт курсор идущим к подменю, то есть находящимся в его безопасной области (см. 9.2) → `layer.showSubmenu(item)`:

1. Ленивое построение DOM уровня, если он ещё не создан.
2. `calculateSubmenuPosition` относительно `getBoundingClientRect()` пункта-владельца.
3. **Усечение цепочки:** все уровни глубже текущего и в другой ветке скрываются. Открыли «Экспорт → PDF», навели на «Скачать» — цепочка обрезается до «Скачать».
4. `aria-expanded="true"` на пункте-владельце, перенос в конец `<body>`, `showPopover()`.
5. Показ фокус **не** переносит, и оба пути приводят к одному состоянию: у мышиного фокус и отметка и так стоят на владельце, потому что наведение выделило его (см. 9.1), а клавиатурный переносит движок, первым пунктом нового уровня. Родительский уровень остаётся тем, кто отвечает на клавиши.

### 6.3. Закрытие

`close()`:

1. `hidePopover()` по всем элементам цепочки, от глубоких к корню, с отложенным снятием (см. 9.3).
2. Сброс `aria-expanded`, `data-active`, таймеров hover intent и отложенного показа переоткрытия.
3. Возврат фокуса на элемент-владелец, иначе фокус провалится в `<body>`. Закрытие по внешнему событию — клик по странице, скролл, `resize` — фокус не возвращает: он принадлежит не меню.
4. DOM не уничтожается — меню переиспользуется при следующем открытии. Ленивость из ТЗ (Этап 4) реализуется здесь: за время жизни строятся только реально открывавшиеся ветки.

Отдельно от `close()`: **меню закрывает клик по любому доступному пункту**, а не только по пункту с действием. Разделитель, отключённый пункт и владелец непустого подменю — ровно три исключения, и они уходят на свои ветки раньше: клик по владельцу открывает подменю, а его собственное действие не зовётся. Закрытие живёт в `finally` обработчика активации, поэтому действие, бросившее исключение, не оставит меню висеть, а само исключение уйдёт наружу. Единственный пропуск — действие, успевшее вызвать `open()`: закрытие тогда не выполняется, иначе «открыть меню в другом месте» убило бы то, что только что открыто.

`destroy()` снимает слушатель с контейнера, убивает таймеры, скрывает и удаляет все элементы из DOM, зануляет приватные ссылки. Повторный вызов безопасен; любой другой метод после `destroy()` бросает `Error('MyContext: экземпляр уничтожен')`.

## 7. Геометрия

### 7.1. `calculateMenuPosition`

Чистая функция. На вход `{cursorX, cursorY, menuWidth, menuHeight, viewportWidth, viewportHeight, offset, padding}`, на выход `{left, top}`.

По каждой оси независимо строится упорядоченный список кандидатов; берётся первый, помещающийся целиком. Если не помещается ни один — clamp к `padding`.

- X: `cursorX` → `cursorX - menuWidth` (флип влево) → `padding`.
- Y: `cursorY` → `cursorY - menuHeight` (флип вверх) → `padding`.

Условие «помещается» для кандидата `p` с размером `s` на оси с вьюпортом `v`: `p + s + padding <= v` и `p >= padding`.

Порядок кандидатов реализует правило «ближе к курсору побеждает», поэтому не требуется сравнивать свободное место по осям между собой. Clamp — последний рубеж, он даёт гарантию критерия 2 даже когда меню шире вьюпорта.

### 7.2. `calculateSubmenuPosition`

Чистая функция. На вход `{anchorRect, menuWidth, menuHeight, viewportWidth, viewportHeight, offset, padding}`, на выход `{left, top}`.

- **X:** предпочтительно справа, `left = anchorRect.right + offset`. Не помещается → флип влево: `left = anchorRect.left - menuWidth - offset`. Не помещается → clamp к `padding`.
- **Y:** только clamp, без флипа. `top = anchorRect.top`, затем поднять так, чтобы `top + menuHeight <= viewportHeight - padding`. Если не помещается ни сверху, ни снизу — `top = padding`, дальше работает внутренний скролл уровня.

Разница в поведении по Y не совпадение: у подменю нет собственного курсора, и нативные ОС не «выворачивают» его относительно пункта, а сдвигают, сохраняя выравнивание по верху, пока есть куда сдвигать.

У пункта, чьё подменю флипнулось по X, шеврон разворачивается: `data-chevron="left"`.

### 7.3. Замер вслепую

UA-стили задают элементу с атрибутом `popover` значение `display: none` до `showPopover()`. Наивный замер до показа даёт `0×0` и ломает всю геометрию. `layer.js` выполняет замер так: инлайново ставит маску `display: flex; position: fixed; left: -9999px; top: 0; visibility: hidden; transform: none`, подключает элемент в конец `<body>` (7.4), читает `getBoundingClientRect()`, снимает маску, записывает реальные координаты и вызывает `showPopover()`. Шаги перечислены в том же порядке в 6.1, и три места в нём обязательны:

- **Подключение до замера.** У отцепленного узла нет раскладки, и замер вернул бы нули. Побочный эффект тот же, что требует 7.4: перенос поднимает уровень в конец `<body>`, а порядок отрисовки в Top Layer следует за порядком в DOM.
- **`transform: none` в маске.** Базовое правило `.vc-menu` задаёт `transform: scale(0.96)`, и без обнуления замер шёл бы по уменьшенной рамке, то есть вся геометрия считалась бы по заниженным габаритам.
- **Снятие маски раньше записи координат.** У маски есть собственные `left` и `top`, и обратный порядок стёр бы написанное.

Побочного мерцания нет: на момент измерения элемент невидим, а вход через `@starting-style` начинается с `opacity: 0`.

### 7.4. Порядок отрисовки в Top Layer

Порядок отрисовки элементов Top Layer совпадает с их порядком в DOM. Поэтому перед каждым `showPopover()` элемент переносится в конец `<body>` — иначе глубоко вложенное подменю окажется под ранее созданным соседним подменю.

### 7.5. Отступ от краёв

`styles/mycontext.css` задаёт каждому уровню `max-height: calc(100dvh - 2 * var(--vc-padding))` при `--vc-padding: 8px`. JS не знает про `max-height`: он меряет уже сжатую высоту и работает с фактом. Единственное дублирование — `SAFETY_PADDING = 8` в `constants.js` для clamp-расчётов; совпадение с CSS-переменной фиксируется e2e-тестом.

## 8. Рендеринг

### 8.1. Иконки

`renderIcon(config)` возвращает элемент, готовый к вставке в слот шириной `--vc-icon-size`.

- **Эмодзи:** `<span class="vc-icon" aria-hidden="true">`. Набор `user-select: none`, `font-variant-emoji: emoji`, явный список эмодзи-шрифтов. `aria-hidden` достаточно: текст пункта уже озвучивается, дублирование не нужно.
- **SVG:** инлайн-узел с `currentColor`. Разбор через `DOMParser`, затем санитизация. Белый список задан **и по элементам, и по атрибутам**: список вычитающих правил по атрибутам не работает, потому что следующий вектор обнаруживается уже после его написания, а мост из недоверенной разметки в стили страницы через `class` и `data-*` остаётся открытым при любом их перечислении.
  - *Элементы:* `svg, path, circle, ellipse, rect, line, polyline, polygon, g, defs, use, clipPath, mask, title, linearGradient, radialGradient, stop`. Всё остальное удаляется **вместе с поддеревом**; узлы комментариев и инструкций обработки удаляются, остаются только элементы и текст.
  - *Атрибуты:* остаются только геометрия и представление — `d, cx, cy, r, rx, ry, x, y, x1, y1, x2, y2, width, height, points, pathLength, transform, gradientTransform, gradientUnits, patternUnits, patternContentUnits, clipPathUnits, maskUnits, maskContentUnits, markerWidth, markerHeight, markerUnits, refX, refY, orient, offset, viewBox, preserveAspectRatio, fill, fill-rule, fill-opacity, stroke, stroke-width, stroke-linecap, stroke-linejoin, stroke-miterlimit, stroke-dasharray, stroke-dashoffset, stroke-opacity, opacity, color, stop-color, stop-opacity, font-family, font-size, font-weight, text-anchor, dominant-baseline, letter-spacing, word-spacing, clip-path, clip-rule, mask, filter, marker-start, marker-mid, marker-end, display, visibility, vector-effect, shape-rendering, paint-order, color-interpolation, color-interpolation-filters, id`. Всё остальное удаляется безусловно, включая `class`, `data-*`, `style`, `on*`, `tabindex`, `overflow`, `pointer-events`, `role` и любые `aria-*`: у очищенной инлайновой иконки нет легитимного применения ни к одному из них, а оформление задаёт CSS библиотеки селектором по слоту. Объявления пространств имён `xmlns*` не проходят по списку и удаляются; каноническое пространство SVG выставляется корню принудительно, поэтому результат не зависит от того, что написал автор.
  - *Ссылки:* `href` и `xlink:href` допускаются только как фрагмент того же документа, то есть значение начинается с `#`. Проверка идёт по `localName` вместе с `namespaceURI`, а не по строке квалифицированного имени: объявление `xmlns:xl` и атрибут `xl:href` иначе дают имя, не совпадающее ни с одним правилом, и внешняя ссылка проходит. Значение любого атрибута, содержащее `url(`, допускается только если каждое вхождение ссылается на фрагмент того же документа — с допуском пробелов вокруг имени и кавычек внутри `url( "#id" )`, поскольку отбрасывание кавычек ломало бы легитимные иконки без выигрыша в безопасности. Смешанное значение, содержащее и внутренний, и внешний `url(`, отбрасывается целиком.
  - *Корень:* `width` и `height` в `100%`, `aria-hidden="true"`, `focusable="false"`, `overflow="hidden"`, плюс принудительное `xmlns`. Последнее важно: без `overflow="hidden"`.presentation-атрибут автора перебивает правило UA-стилей и unclips вьюпорт иконки, а вместе с `pointer-events` даёт оверлей, перехватывающий клики, — тот же результат, ради которого введено правило для `style`, но достигнутый без `style`.
  - *Известный остаток, осознанно не закрытый:* CSS-escape-последовательности вида `\75 rl(...)` регуляркой не ловятся по определению. Полноценная защита потребовала бы разбора CSS, то есть либо запрещённой зависимости, либо большого самописного парсера с собственными ошибками. Соразмерная мера — CSP владельца страницы; это ответ уровня платформы, а не библиотеки. Ограничение фиксируется в README.
  - *Принятые ограничения, фиксируемые в README:* внешний спрайт-лист через `use` больше не работает, иконку нужно инлайнить; `style` не годится для презентации, только presentation-атрибуты; сохранённый `id` разрешает `use href="#id"` ссылаться на элементы **хост-страницы** после вставки узла, поэтому генерируемые самой библиотекой идентификаторы уровней обязаны начинаться с префикса `vc-`.
- **Растр:** `<img class="vc-icon" alt="…" draggable="false" decoding="async">`. `alt` обязателен. Значение прогоняется через `URL`-парсер, чтобы отсечь `javascript:` и `data:text/html`.

### 8.2. Сетка пункта

CSS Grid с колонками фиксированной ширины `[--vc-icon-size] 1fr [--vc-chevron-size]`. Обе колонки зарезервированы **всегда**, на всех уровнях, независимо от наличия иконок и подменю. Это даёт соосность лейблов при любом наборе пунктов и исключает сдвиг текста при открытии подменю.

### 8.3. Соседние, а не вложенные подменю

У пункта с подменю в объекте `MenuItem` лежит поле-владелец, а сам `div.vc-menu[popover]` находится в `<body>` рядом с корневым меню, а не внутри пункта. Связь «пункт ↔ его подменю» держится полем `owner`.

Причины, по которым вложенность невозможна, идут пакетом:

- `position: absolute` внутри скроллируемого контейнера позиционируется относительно контейнера, а не вьюпорта, — подменю обрезалось бы на длинных меню;
- `backdrop-filter` на родителе создаёт containing block для потомков;
- анимация `scale` на родителе ломает координаты потомков.

Соседство снимает все три. Плата в том, что `role="menuitem"` не имеет прямого контейнера-`menu`; WAI-ARIA допускает вложенные меню отдельными `menu`, а `aria-owns` на пункте мы всё равно проставляем для скринридеров.

### 8.4. Ленивость и хранение коллбэков

Строится уровень целиком при первом открытии; следующий уровень — когда он реально показан. `action`-коллбэки извлекаются в `Map` по внутреннему ключу пункта (см. 8.5), а не по `id`: элементы меню не несут функций, и ключ обязан быть устойчив к чужой разметке. Карта пополняется только — ключи исчезнувших при перестроении пунктов остаются, но недостижимы, потому что обращения идут от DOM.

### 8.5. Точки входа рендерера

`renderLevel(items, context)` возвращает `LevelElement`, `renderItem(item, context)` — один `menuitem`. Оба принимают контекст с `levelIndex`, чтобы `aria-level`, `aria-setsize`, `aria-posinset` вычислялись из позиции в уровне, а не из пользовательских данных. Коллбэки `action` извлекаются в `Map` по внутреннему ключу пункта, и ключ этот — `${menuId}:${itemIndex}`, где `menuId` уникален по всем уровням всех экземпляров, делящих одну карту. Ключ из `levelIndex` был бы недостаточен: два корневых меню на странице дали бы `0:0` дважды, и активация пункта одного вызвала бы колбэк другого. Пользовательский `id` в ключ не входит вовсе — он необязателен и может повторяться, — и копируется только в `data-id`.

## 9. Взаимодействие

### 9.1. Клавиатура

Роуминг-фокус: отмечен не более чем один пункт открытого уровня, и он же единственный с `tabindex="0"`; остальные `tabindex="-1"`. Разделители и отключённые пункты в цикле не участвуют и отметки не получают. Фокус ставится явно после позиционирования, а не через автофокус `showPopover()`.

Открытое и нетронутое меню выделения не имеет: сразу после открытия `data-active` нет ни на одном уровне, а фокус стоит на самом элементе уровня. Состояние «выделения нет, но уровень отвечает на клавиши» достижимо по построению, и клавиши разбирает движок — по цели события, а не по последней отмеченной строке.

| Клавиша | Поведение |
|---|---|
| `ArrowDown` / `ArrowUp` | Циклический переход по доступным пунктам уровня; без активного пункта — первый и последний |
| `ArrowRight` | Открыть подменю текущего пункта, фокус в его первый пункт. Нет подменю — ничего |
| `ArrowLeft` | Закрыть текущий уровень, фокус на пункт-владелец. На корневом уровне — закрыть всё |
| `Enter` / `Space` | Активировать, и меню закрывается (см. 6.3). У пункта-владельца активация означает открытие подменю, `action` не вызывается. Активного пункта нет — ничего |
| `Escape` | Закрыть текущий уровень; на корневом — всё меню |
| `Home` / `End` | Первый / последний доступный пункт уровня |
| `Tab` | Закрыть всё меню, фокус на элемент-владелец |

Визуальное состояние активного пункта ведёт атрибут `data-active`, и он же единственный носитель подсветки: правила `.vc-item:hover` в таблице стилей нет, иначе у пункта было бы два независимых источника подсветки, а «последнее взаимодействие выигрывает» стало бы невыполнимым (2026-09-28, 3.1). Кольца фокуса нет ни на пункте, ни на уровне: признак выделения только заливка (см. 11, «Доступность оформления»).

Кто последним тронул пункт, тот и держит выделение, и отдельного правила приоритета для этого не требуется. Наведение мышью вызывает тот же переход, что и клавиша, только без долистывания списка: пункт под курсором и так виден. Поскольку активный пункт всегда последний выставленный, «следующий от того, что под курсором» получается само: мышь перебивает клавиатуру, клавиатура мышь. Курсор над невыбираемой строкой — разделителем, отключённым пунктом, полями уровня — выделение не меняет: сбрасывать там нечего, а мигание вышло бы на разделителе высотой в один пиксель, который курсор пересекает постоянно. Уход курсора с дерева меню сбрасывает выделение на всех уровнях и возвращает фокус на элемент корневого уровня, если фокус был в меню; с самой страницы меню фокус не отбирает.

Typeahead-поиск по первым буквам не реализуется: объём кода заметно превышает заявленные требования.

### 9.2. Hover intent

`hoverIntent.js` ничего не помнит о траектории. Он получает точку и безопасную область и отвечает на один вопрос: внутри ли область. Закрытие планируется тогда и только тогда, когда области нет — то есть подменю не открыто — или точка вне прямоугольника; попадание внутрь или на границу снимает отложенное закрытие. Точка на границе считается принадлежащей области: переход к подменю проходит по её собственной кромке, и исключительная граница планировала бы закрытие ровно на пути к пункту.

Область считает оркестратор — только у него есть пара «владелец + подменю», разворот подменю по X и обе рамки. Это **прямоугольник самого подменю, расширенный** по `SUBMENU_OFFSET` в сторону пункта-владельца и по `SAFE_AREA_BUFFER = 30` по трём остальным сторонам. `hoverIntent` остаётся чистой геометрией и о DOM не знает (см. 4, «Архитектура»).

Почему не клин из точек курсора, каким механизм был в первой версии: клин строился из позиций, где курсор покинул владельца, где впервые вошёл в подменю, и последней принятой точки, и вырождался ровно там, где важен. Движение к пункту подменю почти всегда идёт по прямой, а площадь полувырожденного треугольника на прямой равна нулю, то есть защищённым оказывался бы редкий случай, а не основной. У клина нет ширины: она даётся только кривизной траектории.

Прямоугольник вырождаться не может. Отрезок между точкой пункта-владельца и точкой подменю лежит в выпуклой оболочке двух прямоугольников, а зазор между ними равен ровно `SUBMENU_OFFSET`, то есть покрыт расширением в сторону владельца. Расширение на 30 px по всем четырём сторонам было бы ошибкой: накрыло бы край 26 px **любого** пункта родительского уровня, и уход на соседний пункт перестал бы закрывать подменю.

Случай, когда подменю не поместилось ни справа, ни слева и было прижато к `padding`, расширением не покрыт: зазор до владельца там больше `SUBMENU_OFFSET`. Переход через него держит вход курсора в само подменю, снимающий отложенное закрытие, — ровно как страховочный таймер. Полагаться на то, что `pointerenter` всегда сопровождается `pointermove` внутри того же уровня, значило бы завязать корректность на порядок событий, поэтому шаг объявлен явно.

Курсор вне области запускает таймер `CLOSE_GRACE_MS = 200`; возврат курсора отменяет его. Открытие другого пункта сбрасывает оба отложенных действия. Позиция курсора в момент ухода с пункта-владельца больше нигде не хранится — она ничего не решает, потому что область приходит из геометрии подменю, а не из траектории.

Задержка `OPEN_GRACE_MS = 250` перед открытием подменю нужна по той же причине, что и защита от ложных закрытий, только с обратной стороны: без неё подменю вспыхивает на каждом пункте, мимо которого курсор пробегает вниз по списку, — то самое дёрганье, которое запрещает критерий 3. Задержка отсчитывается от первого наведения на пункт-владелец и сбрасывается при уходе курсора. Удержание кнопки мыши у пункта-владельца открывает его подменю немедленно, минуя задержку, — как в нативных ОС.

### 9.3. Анимация входа и выхода

Вход целиком на CSS: `@starting-style` и `transition-behavior: allow-discrete` дают появление из `opacity: 0; scale(.96)` без единой строки JS.

Выход — единственное место, где JS обязан вмешаться: `hidePopover()` мгновенно убирает элемент из Top Layer, поэтому вызов откладывается на `animationDuration`, и только затем выполняется. Отсюда три обязательных правила:

- Закрытие отложено на `animationDuration`, и закрывает его **таймер**. Слушателя `transitionend` нет, и порядок обратный: выходной переход *вызывается* `hidePopover()`, поэтому единственный вызывающий его код — таймер, и к моменту вызова переход ещё не начался слушать. Слушатель, поставленный заранее, способен увидеть только входной переход, уже летящий на момент `hide()`, что делает закрытие недетерминированным.
- Затухание при закрытии ведёт **явное состояние `data-vc-closing`**, а не потеря `:popover-open`. Пока элемент показан, он и `:popover-open`, поэтому смена одного лишь поповер-состояния стиль не меняет и переход не запускает: меню стояло бы непрозрачным все `animationDuration`, а затухание началось бы уже после ухода из Top Layer, где `allow-discrete` ещё держит элемент отрисованным и способным перехватить клик. На время закрытия `pointer-events` становится `none`, чтобы погасающий элемент не брал на себя события ни при каком порядке вызовов. Атрибут снимается при показе;
- повторное открытие во время закрытия отменяет отложенный `hidePopover()` — иначе только что открытое меню исчезнет; отслеживается токен поколения, отложенное действие недействительно, если поколение изменилось;
- `prefers-reduced-motion: reduce` обнуляет и CSS, и JS: `layer` читает `matchMedia` в момент закрытия и пропускает отложенный `hidePopover()` целиком, иначе невидимое меню осталось бы в Top Layer и съедало бы клики по странице.

### 9.4. Разделение своего скролла и скролла страницы

Событие `scroll` не всплывает, но доходит до `window` в фазе захвата, поэтому слушатель на `window` увидит и прокрутку внутреннего списка меню. В обработчике проверяется, что цель не находится внутри `.vc-menu`; иначе меню захлопнулось бы при прокрутке длинного списка. Слушание — capture + `passive`, чтобы не блокировать скролл страницы.

### 9.5. Изоляция правого клика

Пока меню открыто, слушатель `contextmenu` на `document` глушит браузерное контекстное меню только если цель находится внутри дерева меню. Правый клик снаружи закрывает наше меню; если он попал в привязанный контейнер, его собственный обработчик тут же открывает меню заново в новой точке — так ведут себя нативные ОС. Снаружи контейнера библиотека не подавляет ничего.

### 9.6. Триггеры закрытия

Клик вне дерева меню (`pointerdown` в фазе захвата, чтобы обогнать обработчики пунктов) — **включая сам привязанный контейнер**: исключение снято, правый клик идёт своим путём и меню по нему не мигает, — `Escape`, скролл страницы, `resize` окна, клик по любому доступному пункту.

Уход курсора с дерева меню в этот список **не входит**. Он закрывает подменю, и то все, а корневой уровень оставляет на месте: у него нет владельца и закрывать ему нечего. Меню, открытое в нативном стиле, не следует за курсором, и убирать его приходится правым кликом, `Escape` или кликом по пункту.

## 10. Доступность

- `role="menu"` на каждом уровне, `aria-label` из `options.label`.
- `role="menuitem"` на пунктах; `aria-disabled` (не атрибут `disabled`, так как это не кнопки) на отключённых; `aria-haspopup="menu"` и `aria-expanded` на владельцах подменю; `aria-owns` на владельцах подменю для скринридеров.
- `role="separator"` на разделителях, `aria-orientation="horizontal"`. Разделитель не получает фокус.
- `aria-level`, `aria-setsize`, `aria-posinset` вычисляются из позиции в уровне.
- Полное управление с клавиатуры по таблице 9.1.

Два расхождения с формулировками ТЗ, оба сознательные. `aria-haspopup` выставляется значением `"menu"`, а не `"true"`: по ARIA 1.2 `true` является синонимом, но `menu` точнее и так пишут в спецификации WAI-ARIA Authoring Practices; проверка axe различает эти значения. Идентификаторы для `aria-owns` генерируются при создании уровня, так как соседние подменю не вложены в разметку пункта (8.3).

## 11. Стили

`styles/mycontext.css` — единственный источник правды по визуалу. Токены:

```
--vc-bg  --vc-bg-solid  --vc-text  --vc-muted  --vc-hover-bg  --vc-active-bg
--vc-scrollbar-thumb  --vc-separator  --vc-shadow
--vc-radius  --vc-padding  --vc-item-height  --vc-font  --vc-font-size
--vc-icon-size  --vc-chevron-size  --vc-animation-duration
```

**Темы.** На корневом элементе всегда стоит `data-vc-theme` со значением `auto` / `light` / `dark`. Каскад: значения светлой темы базовые; `@media (prefers-color-scheme: dark)` переопределяет их только для `[data-vc-theme="auto"]`; селектор `[data-vc-theme="dark"]` переопределяет всегда. Селектор атрибута специфичнее медиазапроса, поэтому явный `dark` побеждает системную настройку, а `auto` остаётся живым. Смена темы ОС подхватывается без перерисовки меню.

**Стекло с запасным вариантом.** Полупрозрачный фон и `backdrop-filter: blur(20px) saturate(180%)`. Чтобы в браузере без `backdrop-filter` фон не стал нечитаемым, `@supports not (backdrop-filter: blur(1px))` подставляет непрозрачный `--vc-bg-solid`. Проверяется в webkit.

**Анимации.** Вход через `@starting-style` (9.3). Выход — отложенный `hidePopover()`. Медиазапрос `@media (prefers-reduced-motion: reduce)` обнуляет `--vc-animation-duration`, отключает `transform` **и дополнительно объявляет `transition: none` для меню и его потомков**. Последнее обязательно и не избыточно: `applyAnimationDuration` пишет `--vc-animation-duration` в инлайновый стиль элемента, а инлайновое объявление перебивает любое авторское правило, включая правило внутри медиазапроса, — поэтому одной подмены токена хватает только до первого вызова публичного API. `transition: none` инлайном не перебивается, потому что инлайнового `transition` никто не пишет, и это единственная форма, работающая без `!important`.

**Доступность оформления.** Активный пункт красит единственное правило `.vc-item[data-active]` и только `background`: текст строки остаётся `--vc-text`. Второго носителя подсветки нет — правила `.vc-item:hover` в таблице стилей не существует (2026-09-28, 3.1).

**Кольца фокуса нет нигде.** `outline: none` стоит на `.vc-menu` и `.vc-item`, и это обязательная часть решения, а не аккуратность: UA рисует своё кольцо каждому узлу, чей фокус считает видимым, и на программно сфокусированном элементе уровня оно появляется само — замерено в Chromium как `outline: auto 1px rgb(16,16,16)` на голом узле с `tabindex="-1"`. Удаление авторского правила кольцо не отменяет, а отменяет его замену. Признак фокуса — заливка активного пункта (2026-09-28, раздел 2, решение 1). `.vc-list` объявления `outline` не получает: фокус на нём невозможен, и правило было бы мёртвым. Охрана таблицы стилей проверяет и сам факт двух `outline: none`, и отсутствие `:focus-visible`: кольцо, вернувшееся под другим именем, охрана не видит.

**Контраст активного пункта** — требование, а не вкусовое предпочтение: composited-фон активного пункта и текст на нём обязаны давать не меньше 4.5:1 в обеих темах. Фон меню полупрозрачный, поэтому измеряется композит — заливка пункта, затем фон меню, затем страница под стеклом, — а не сам цвет токена. Заливка по умолчанию тонированная, `var(--vc-hover-bg)`, и текст на ней `--vc-text`: в светлой палитре это 14.5:1, запас есть. Первая реализация давала сплошной акцент с белым текстом и 1.29:1 в светлой и 2.07:1 в тёмной теме, то есть текст выделенного пункта был практически невидим, и ни один тест этого не замечал, поскольку проверял только непрозрачность и отличие от обычного пункта. Порог 4.5:1 проверяется там, где состояние достижимо; недостижимое «отключённый и активный» (9.1) держит пол 4:1 — не AA, а границу, за которой палитра считается уехавшей. `--vc-active-bg` остаётся точкой настройки: отступление от равной по умолчанию мышиной заливке — осознанный отказ пользователя от гарантии библиотеки.

## 12. Обработка ошибок

- **Валидация конфигурации** — в конструкторе, рекурсивно по всем уровням, чтобы битая конфигурация падала сразу, а не при первом наведении. `TypeError` с путём до узла, например `items[2].icon.type: ожидается 'emoji' | 'svg' | 'raster'`. Проверяются: непустой массив; непустая строка `label` у пункта; `action` — функция; `submenu` — массив; соответствие `icon` одному из трёх вариантов.
- **Отказ окружения.** Отсутствие `HTMLElement.prototype.showPopover` диагностируется в `attach()`, а не на импорте, чтобы `import` оставался безопасным в SSR-окружении. Сообщение называет конкретное требование.
- **Иконки — fail-soft.** Неразобранный SVG не роняет меню: в слот встаёт пустое место, в `console.warn` уходит одно предупреждение. Меню обязано работать.
- **Использование после `destroy()`** бросает `Error`. Сам `destroy()` идемпотентен.

## 13. Тестирование

Второго тестового раннера нет: всё через `@playwright/test`.

**Юнит-тесты чистых функций** (`positioner.js`, `hoverIntent.js`) — таблицы кейсов без браузера: четыре угла, крошечный вьюпорт, меню шире вьюпорта, флип подменю влево и вправо, clamp по вертикали, безопасная область (точка вне прямоугольника, точка на границе, то без области вовсе), таймер. Инвариант «меню целиком внутри вьюпорта минус padding» проверяется на детерминированной сетке координат.

**Юнит-тесты в браузере** (`icons.js`, валидация конфигурации, `renderer.js`) — пустая страница, импорт модуля, прогон таблицы `renderIcon`: проверка санитизации (ни `<script>`, ни `on*` не остаётся) и равенства координат лейблов у пунктов с иконкой и без.

**E2E** (`index.html` через демо) — на трёх движках:

- открытие в каждом углу с проверкой `boundingBox()` внутри вьюпорта;
- вложенность 4 уровней без ложных закрытий;
- прямое движение к дальнему пункту подменю не роняет его;
- уход курсора с дерева меню закрывает подменю, а корневой уровень оставляет;
- полный сценарий только с клавиатуры;
- все три типа иконок и соосность лейблов;
- ПКМ по меню не открывает системное меню (`defaultPrevented === true`);
- тёмная тема через `emulateMedia`;
- `reducedMotion: 'reduce'` — меню видно сразу, без ожидания;
- после `destroy()` в DOM нет `.vc-menu` и `contextmenu` на контейнере ничего не открывает.

`package.json` содержит только `devDependencies` (`@playwright/test`, `typescript`) и три скрипта: `test`, `typecheck`, `serve`. Ни одной рантайм-зависимости и ни одного поля `dependencies` — это проверяемо, а не обещанием.

`Demo/scenarios.js` содержит наборы меню для демонстрации всех возможностей: вложенность 4 уровней, все три типа иконок, отключённые пункты, список длиннее вьюпорта.

## 15. Критерии готовности

1. Библиотека — чистый ES-модуль, импортируется без транспиляции; в `package.json` нет поля `dependencies`.
2. Меню не выходит за видимые границы вьюпорта ни при каком расположении точки клика, включая углы и окна меньше меню.
3. Вложенные меню открываются стабильно, без дёрганий и ложных закрытий при движении мыши к ним.
4. Все три формата иконок работают; текстовые метки строго соосны независимо от наличия иконок.
5. Меню полностью функционально при использовании только клавиатуры.
6. Внешний вид соответствует нативным системным меню; анимации не блокируют взаимодействие, `prefers-reduced-motion` отключает их мгновенно.
7. `destroy()` не оставляет слушателей и DOM-узлов.

## 16. Что осознанно не входит

- Typeahead-поиск по первым буквам.
- Горячие клавиши и подписи сочетаний в пунктах меню (прямое требование ТЗ).
- `max-height` с автоподгонкой числа пунктов — вместо него внутренний скролл.
- Позиционирование через CSS Anchor Positioning: неравномерная поддержка в браузерах и прямое противоречие Этапу 3 ТЗ.
- Подавление системного контекстного меню вне привязанного контейнера.
- Сборка в единый дистрибутивный файл.
