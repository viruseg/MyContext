# MyContext

Контекстные меню для браузера на чистом ES-модуле. Без рантайм-зависимостей, без
сборки, с Top Layer, неограниченной вложенностью подменю и полной клавиатурной
навигацией по открытому меню.

## Назначение

MyContext показывает меню по правому клику в точке, где стоит курсор, и держит его
внутри вьюпорта: корневой уровень появляется рядом с курсором, каждый уровень
подменю — рядом со своим пунктом-владельцем и разворачивается влево, когда справа
не хватает места. Вложенность не ограничена, список длинного уровня прокручивается
внутри рамки, а само меню живёт в Top Layer, поэтому не перекрывается ни заголовком,
ни модальным диалогом, ни `z-index` страницы.

- **Ноль зависимостей.** В `package.json` нет поля `dependencies`; в рантайме нет ни
  одного импорта, кроме вашего кода.
- **Ноль сборки.** Модуль — обычный ES-модуль из репозитория, браузер читает его как
  есть. `index.js` экспортирует ровно один символ — класс `MyContext`.
- **Меню в Top Layer.** Каждый уровень — свой элемент с `popover="manual"`, и все
  они лежат соседними узлами в `<body>`, а не внутри пункта: `backdrop-filter` и
  анимация масштаба на родителе создают containing block и ломают позиционирование
  относительно вьюпорта.
- **Клавиатура.** После открытия меню целиком проходится с клавиатуры, без единого
  движения мыши.
- **Зоны прокрутки.** Длинный список листают две зоны у краёв рамки, а системной
  полосы у списка нет: кроме своей толщины, сужавшей колонку подписей, у неё не было
  ничего. Зоны не входят в кольцо клавиатурной навигации и скрыты от чтения с
  экрана, а у упора гаснут, а не исчезают, — иначе список уехал бы из-под курсора
  ровно тогда, когда зона перестала его вести.
- **Темы.** `auto` следует за системной схемой, `light` и `dark` задают её явно.
  Вся палитра — в CSS-переменных.

## Требования

Жёсткое требование одно — **Popover API и Top Layer**, то есть
`HTMLElement.prototype.showPopover`. Без него `attach()` бросает `Error` с
названием требования, а меню показать нечем: всё построено на `showPopover()` и
`hidePopover()`. Базовая линия движков: Chrome и Edge 114, Firefox 125, Safari 17.

Появление и исчезновение уровней анимируются через `@starting-style` и
`transition-behavior: allow-discrete`; это дополнительное требование, и там, где оно
не поддержано, меню остаётся рабочим, но переходов не будет.

`prefers-reduced-motion: reduce` обрабатывается и в CSS, и в JS: длительность
обнуляется, а отложенный `hidePopover()` не ставится вовсе (см. «Поддержка тем и
`prefers-reduced-motion`»).

## Установка

```bash
npm install
```

Зависимости устанавливаются только для разработки: Playwright, TypeScript и типы
Node. В рантайме библиотека не нуждается ни в чём.

Подключение состоит из двух файлов — таблицы стилей и модуля:

```html
<link rel="stylesheet" href="./styles/mycontext.css" />
<script type="module">
  import { MyContext } from './src/index.js';
</script>
```

В `package.json` нет ни поля `dependencies`, ни полей `main` и `exports`, и пакет
помечен `private`: библиотека не публикуется и не проходит через сборщик. Её
подключают файлами — скопировать `src/` и `styles/` к себе либо отдавать
статикой оттуда, где они лежат.

Модуль обязательно должен отдаваться по `http(s)`, а не с `file://`: браузер
запрещает загрузку ES-модулей с файловой системы. Штатный способ — любой
статический сервер; в репозитории для этого есть `npm run serve`, он же поднимает
демо (см. «Демо»).

Подключать таблицу стилей обязательно: в ней лежат и геометрия (сетка пункта,
`max-width`/`max-height` уровня), и палитра, и анимации. Без неё меню откроется, но
не будет выглядеть меню.

## Использование

```js
import { MyContext } from './src/index.js';

const menu = new MyContext(
  [
    {
      label: 'Открыть',
      icon: { type: 'emoji', value: '📂' },
      action: () => console.log('открыть'),
      submenu: [
        { label: 'Недавние', action: () => console.log('недавние') },
        {
          label: 'Проект',
          icon: {
            type: 'svg',
            value: '<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 16 16">'
              + '<path d="M2 2h12v12H2z" fill="currentColor"/></svg>',
          },
          submenu: [
            { label: 'Черновик', action: () => console.log('черновик') },
            { label: 'Готово', action: () => console.log('готово') },
          ],
        },
      ],
    },
    { type: 'separator' },
    {
      label: 'Вставить картинку',
      icon: { type: 'raster', value: '/icons/picture.png', alt: 'Картинка' },
      action: () => console.log('вставить'),
    },
    {
      label: 'Склеить два файла',
      icon: { type: 'emoji', value: '🧩' },
      // Отключённый пункт не входит в цикл клавиатурной навигации, мышью по нему
      // не попасть, а его действие не зовётся. Непустое подменю у отключённого
      // пункта не делает его владельцем: шеврона, `aria-haspopup` и `aria-owns` у
      // него не будет, и раскрывать всё равно нечего.
      disabled: true,
      submenu: [{ label: 'Что угодно' }],
    },
  ],
  { label: 'Меню файла', theme: 'auto' },
);

menu.attach(document.querySelector('#workspace'));
```

`attach` подписывается ровно на одно событие — `contextmenu` на переданном
контейнере, и подавляет системное меню внутри него. **Открывается меню правым
кликом по контейнеру.** Единственный программный путь — `open({ x, y })`, и он же
нужен для сценариев вроде «меню по кнопке»:

```js
document.querySelector('#paste').addEventListener('click', (event) => {
  menu.open({ x: event.clientX, y: event.clientY });
});
```

**Клавиатурного способа открыть меню через API нет.** `attach` не подписывается ни
на `keydown`, ни на `keyup`, и на привязанном контейнере `Enter`, `Space` и `F10`
не открывают ничего — это можно проверить на любом из трёх движков. Chromium при
этом сам синтезирует `contextmenu` по клавише `ContextMenu` и по `Shift+F10`, то
есть на нём меню всё-таки открывается с клавиатуры; Firefox и WebKit такого не
делают, и ни один из трёх не синтезирует `contextmenu` по `Enter`, `Space` и `F10`.
На документ `attach` вешает свой `keydown` в capture-фазе, но он ловит **только**
`Escape` и закрывает уже открытое меню, а не открывает его. Если меню должно
открываться с клавиатуры, добавьте триггер сами: обычно это кнопка или
`role`-элемент с обработчиком, зовущим `open({ x, y })` по координатам кнопки.

Внутри уже открытого меню клавиатура работает полностью:

| Клавиша | Действие |
| --- | --- |
| `ArrowDown` / `ArrowUp` | следующий / предыдущий доступный пункт, по кругу |
| `Home` / `End` | первый / последний доступный пункт |
| `ArrowRight` | открыть подменю пункта-владельца и перейти в него |
| `ArrowLeft` | закрыть текущий уровень и вернуться на пункт-владелец |
| `Enter` / `Space` | вызвать действие пункта и закрыть меню; у пункта-владельца — открыть подменю; без выделенного пункта ничего не делает |
| `Escape` | закрыть текущий уровень; на корневом — всё меню |
| `Tab` | закрыть меню и вернуть фокус контейнеру |

Разделители и отключённые пункты в цикл навигации не входят и подсветки не получают.
Клик по пункту-владельцу открывает его подменю, а собственное действие владельца не
зовёт — ни мышью, ни с клавиатуры. Выделения сразу после открытия нет, а признак
выделения один: заливка активного пункта, кольца фокуса нет ни на пункте, ни на
уровне.

Меню само закрывается при клике левой кнопкой вне дерева меню — включая сам
привязанный контейнер, — при правом клике вне дерева меню и вне привязанного
контейнера, при клике по доступному пункту меню, при `Escape` вне меню, при прокрутке
страницы и при изменении размеров окна. Прокрутка внутри длинного списка меню его
не закрывает — и список чужого экземпляра на той же странице тоже, хотя два
экземпляра на странице обычны. Внутренним для прокрутки считается любой скролл,
цель которого лежит в дереве какого угодно меню, а не только этого: закрытие
вызывается уездом страницы из-под привязанного контейнера, а список под ним не уезжает
и его геометрию не меняет, так что листание чужого меню не должно сносить соседнее.

У длинного списка нет полосы прокрутки: его листают колесом над самим списком,
пальцем и клавишами, а с мыши — наведением на зону у края рамки: зон две, и высота
каждой задана токеном `--vc-scroll-zone-height`. Показываются зоны у того уровня, чей
список не помещается, и у самого края гаснут, а не исчезают: исчезновение сдвинуло бы
список из-под курсора ровно тогда, когда он перестал им двигаться.

Пока курсор держит зону, выделение с пункта снимается: подсветкой горел бы тот, кого
никто не выбирал. А колесо над зоной закрывает меню — вернее, закрывает, если страница
прокручивается: прокручиваться там нечему, колесо уходит странице, и закрытие приходит
вместе с её прокруткой.

Уход курсора с дерева меню его не закрывает: он закрывает подменю, а корневой
уровень оставляет на месте. Открытое в нативном стиле меню не следует за курсором,
и снимают его те же клавиша и клики, что перечислены выше.

Глобальные слушатели закрытия заводятся в `attach`, поэтому список выше работает,
пока экземпляр привязан. Открытый через `open()` без привязки (и после `detach()`)
экземпляр закрывается `close()`, `Escape` и `Tab` внутри меню, а также кликом по
доступному пункту.

### Пункты и подменю

Пункт — объект с полями:

| Поле | Тип | Обязательность |
| --- | --- | --- |
| `label` | `string` | обязательно, непустая строка |
| `id` | `string` | необязательно, копируется в `data-id` и в ключ пункта не входит |
| `icon` | см. «Ограничения иконок» | необязательно; без него слот остаётся пустым, но занимает место |
| `action` | `(event) => void` | необязательно; вызывается по клику и по `Enter`/`Space`, кроме пункта-владельца непустым подменю |
| `disabled` | `boolean` | необязательно |
| `submenu` | `MenuItem[]` | необязательно; непустой массив и отсутствие `disabled` делают пункт владельцем |

Разделитель — это `{ type: 'separator' }`. Имя `type` обязано быть ровно
`'separator'`: конструктор бросает `TypeError` на любое другое значение, так что
опечатка автора не превратится молча в пункт. Лишние поля у разделителя не
отклоняются и просто игнорируются.
Пустое подменю не считается подменю, и пустой корневой массив отклоняется
конструктором: меню без пунктов не рисуется.

`action` получает настоящее событие активации — мышиный клик или клавиатурную
активацию — с настоящей целью. Исключение из обработчика не проглатывается: его
получает вызывающий, а меню закрывается в `finally` — за одним исключением: если
действие само вызвало `open()`, закрытие пропускается, иначе открытое им заново меню
убило бы тот же клик.

## Справочник API

### `new MyContext(items, options?)`

Создаёт меню. Конфигурация проверяется сразу, и экземпляр с негодной конфигурацией
не появляется: бросается `TypeError`, а в сообщении назван путь до поля
(`items[1].submenu[0].label`). Слушателей на страницу конструктор не вешает.

Поля `options`:

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `theme` | `'auto' \| 'light' \| 'dark'` | `'auto'` | оформление всех уровней |
| `animationDuration` | `number`, мс | `140` | вход, выход и задержка отложенного закрытия |
| `label` | `string` | `'Меню'` | доступное имя меню, ставится каждому уровню |

Одна величина `animationDuration` управляет всеми тремя, иначе выход не совпадёт с
задержкой снятия.

Ополя проверяются так же, как пункты, и каждое значение вне перечисленного
отклоняется: неизвестная `theme` иначе попала бы в разметку дословно и тёмное
приложение тихо получило бы светлое меню, а `NaN` в `animationDuration` дал бы
недействительный токен и анимация пропала бы без единой ошибки. Пустой `label`
тоже отклоняется: имя уровня обязано быть читаемым, и подставлять его по умолчанию
значило бы молча записать `aria-label=""`.

### `attach(element)`

Подписывает контейнер на `contextmenu` и вешает глобальные слушатели закрытия.
Повторный вызов переносит привязку: предыдущий контейнер освобождается, иначе у
экземпляра было бы два контейнера. Возвращаемого значения нет.

Бросает `Error`, если экземпляр уничтожен или браузер не умеет Popover API.
Требование проверяется здесь, а не в конструкторе: без привязки экземпляр пригоден
для `open()` там, где автор и так работает со своим поповером, и падать рано было бы
невежливо.

### `detach()`

Снимает подписку с контейнера, ничего не разрушая: экземпляр остаётся пригодным
для `open()`. Вызов без привязки — не операция. Бросает `Error`, если экземпляр
уничтожен.

### `open({ x, y })`

Открывает корневой уровень в точке вызова, координаты вьюпорта, px. На закрытом меню
показ синхронный. На открытом — полный цикл: уровни гаснут на месте, в Top Layer, и
через `animationDuration` корневой показывается в новой точке; под
`prefers-reduced-motion: reduce` цикл проходит за один такт. Уровень и его пункты при
этом не пересоздаются, то есть повторный вызов не заводит второго меню. Фокус встаёт
на элемент уровня, а не на пункт: выделения после открытия нет, и первую же стрелку
разбирает меню, давая крайний доступный пункт — без фокуса на самом уровне открытое
меню было бы мёртвым для клавиатуры. Бросает `Error`, если экземпляр уничтожен.

### `close()`

Закрывает всю цепочку уровней от глубоких к корню, отменяет отложенные открытия и
возвращает фокус привязанному контейнеру. Без привязки фокус возвращать некуда, и
вызов просто скрывает. Повторный вызов безопасен. Бросает `Error`, если экземпляр
уничтожен.

### `destroy()`

Снимает все подписки и висящие задачи, удаляет все уровни из DOM и очищает
внутреннее состояние.

**`destroy()` идемпотентен, а остальные методы после него бросают `Error`.**
Повторный вызов `destroy()` — обычное дело при размонтировании, и ошибка в нём
была бы ошибкой вызывающего кода. `attach`, `detach`, `open` и `close` после
`destroy()` бросают `Error` с сообщением `MyContext: экземпляр уничтожен`: ими
больше нечего делать, и молчаливое отсутствие эффекта хуже явной ошибки.

## CSS-переменные

Переопределяются на `.vc-menu` или на любом его предке.

### Геометрия

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `--vc-padding` | `8px` | минимальный отступ уровня от края вьюпорта |
| `--vc-item-height` | `28px` | высота пункта |
| `--vc-scroll-zone-height` | `16px` | высота зоны прокрутки у края длинного списка |
| `--vc-icon-size` | `16px` | сторона слота иконки |
| `--vc-chevron-size` | `12px` | колонка шеврона |
| `--vc-radius` | `8px` | скругление меню и пунктов |
| `--vc-animation-duration` | `140ms` | вход, выход и задержка отложенного закрытия |

Семь геометрических токенов обязаны совпадать с константами `src/constants.js`:
`--vc-padding` ↔ `SAFETY_PADDING`, `--vc-item-height` ↔ `DEFAULT_ITEM_HEIGHT`,
`--vc-scroll-zone-height` ↔ `SCROLL_ZONE_HEIGHT`, `--vc-icon-size` ↔
`DEFAULT_ICON_SIZE`, `--vc-chevron-size` ↔ `DEFAULT_CHEVRON_SIZE`, `--vc-radius` ↔
`DEFAULT_RADIUS`, `--vc-animation-duration` ↔ `DEFAULT_ANIMATION_DURATION`.
Движок позиционирования измеряет элемент, уже ограниченный этим CSS, и считает
отступ до края вьюпорта равным `--vc-padding`: расхождение сдвигает решение о том, в
какую сторону развернуть меню у края. За вьюпорт рамка при этом не выйдет —
предельные `max-width` и `max-height` выведены из того же `--vc-padding`. Расхождение
с `--vc-item-height`, `--vc-icon-size`, `--vc-chevron-size`, `--vc-radius` и
`--vc-scroll-zone-height` на поведение не влияет вовсе: эти константы читают только
тесты, как зеркала токенов. `options.animationDuration` переопределяет
`--vc-animation-duration` инлайном на каждом уровне, а инлайн перебивает любую вашу
таблицу стилей.

### Типографика

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `--vc-font` | системный стек | гарнитура меню |
| `--vc-font-size` | `13px` | кегль |

### Палитра

| Переменная | По умолчанию (светлая) | Смысл |
| --- | --- | --- |
| `--vc-bg-solid` | `#ffffff` | непрозрачная подложка, подставляется там, где нет `backdrop-filter` |
| `--vc-bg` | `color-mix(in srgb, var(--vc-bg-solid) 72%, transparent)` | фон уровня |
| `--vc-text` | `#1f2023` | текст пункта, в том числе на активном |
| `--vc-muted` | `#6b7280` | шеврон и отключённый пункт |
| `--vc-hover-bg` | `color-mix(in srgb, var(--vc-text) 6%, transparent)` | подсветка пункта под курсором |
| `--vc-active-bg` | `var(--vc-hover-bg)` | заливка активного пункта, отдельная ручка настройки |
| `--vc-separator` | `color-mix(in srgb, var(--vc-text) 12%, transparent)` | рамка уровня и разделитель |
| `--vc-shadow` | `0 8px 28px rgba(15, 18, 25, 0.18)` | тень |

Заливка активного пункта по умолчанию равна мышиной, и это сделано намеренно: выделение
с клавиатуры и с мыши не должно выглядеть по-разному, а кольца фокуса нет нигде, так
что заливка — единственный признак выделения. Отдельный `--vc-active-bg` оставлен
ручкой: сделайте его заметнее, если хотите. Приглушённая подсветка по умолчанию
держит контраст текста 4.5:1 в обеих темах, и измеряется он на композите — заливка
пункта, фон меню и страница под стеклом. Отступление от заливки по умолчанию —
осознанный отказ от этой гарантии.

## Поддержка тем и `prefers-reduced-motion`

Тема задаётся опцией `theme` и попадает в атрибут `data-vc-theme` на каждом
уровне. `auto` оставляет выбор за системной схемой, `light` и `dark` переопределяют
её. Логика выбора палитры целиком в CSS, а модуль только ставит атрибут, поэтому
любой токен переопределяется вашей таблицей стилей и без пересоздания меню. Сменить
же `theme` на живом экземпляре нельзя: атрибут пишется при создании уровня, и
метода смены темы у экземпляра нет.

Тёмная палитра: `--vc-bg-solid` `#1b1d21`, `--vc-text` `#e8eaed`, `--vc-muted`
`#9aa1ab`, `--vc-bg` — 76% подложки против 72% в светлой, `--vc-hover-bg` — 10% текста,
`--vc-separator` — 16% текста,
`--vc-shadow` — `0 8px 28px rgba(0, 0, 0, 0.55)`. Наведение здесь плотнее
(10 % против 6 %): на тёмной подложке та же доля невидимого текста не дала бы строке
признака, а наведение — единственный его носитель.

Медиазапрос темы ограничен `[data-vc-theme="auto"]`: без этого ограничения системная
тёмная схема красила бы и явно светлое меню.

`prefers-reduced-motion: reduce` отключает движение полностью, а не укорачивает
его:

- выключаются переходы как класс свойств — на самом меню и на всех его потомках,
  поэтому шеврон и подсветка пунктов не двигаются тоже. Длительность при этом
  обнуляется правилом медиазапроса, но перебивается инлайновым значением, которое
  ставит уровень, и потому работает именно выключение переходов, а не нулевая
  длительность;
- `transform` у самого меню снимается (поворот шеврона на 180° при развороте
  подменю влево — это признак положения, а не анимация, и он переживает `reduce`);
- отложенный `hidePopover()` не ставится вовсе: под `reduce` в CSS стоит
  `transition: none`, и `display` меняется мгновенно, так что отложенное закрытие
  погасило бы уровень мгновенно — то есть состояние, ради которого отложенность и
  существует, стало бы недостижимым.

Меню под `reduce` видно сразу после открытия, без ожидания кадра.

## Ограничения иконок

Иконка типа `svg` — это **недоверенная разметка**: она приходит от автора пункта, и
подставляется в DOM как есть, поэтому очищается по белым спискам элементов и
атрибутов, а не по набору запретов. Всё, чего в списках нет, удаляется: элемент
вместе с поддеревом, атрибут у каждого уцелевшего элемента. Из прочих узлов
остаются только текст и CDATA. Корневому `svg` принудительно выставляются
`width="100%"`, `height="100%"`, `aria-hidden="true"`, `focusable="false"`,
`overflow="hidden"` и канонический `xmlns`.

Это значит следующее, и лучше знать заранее, чем узнавать об этом на своей странице.

**Иконку нужно инлайнить.** Разметка `type: 'svg'` — это строка в вашем коде, а не
адрес. Внешний спрайт-лист через `use` не работает: ссылки `href` и `xlink:href`
допускаются только фрагментные, то есть `href="#имя"`. Всё остальное — включая
относительный путь, который на любом другом origin уже внешний — вырезается. Внешний
спрайт, отданный с того же origin, тоже вырежется: правило не смотрит на адрес, а
смотрит на форму.

**Презентация задаётся presentation-атрибутами и CSS библиотеки.** Атрибут `style`
вырезается целиком, поэтому задать цвет, прозрачность или позиционирование через
него нельзя. Пишите `fill="currentColor"`, `stroke-width="1.5"` и подобное прямо в
разметке, а мелкие правки делайте селектором по слоту: `.vc-icon-slot > *`
описывает любого ребёнка слота, потому что сам svg-узел класса не получает
намеренно — класс был бы мостом из недоверенной разметки в стили страницы.

**CSS-escape-последовательности вида `\75 rl(...)` санитизация не ловит.** Проверка
значений presentation-атрибутов ищет `url(` как подстроку и убирает атрибут, если
после удаления внутренних `url(#имя)` осталась посторонняя ссылка; escape-последовательность
разбирается уже движком CSS, и до него проверка не доходит. **Это осознанный остаток,
а не недосмотр:** закрыть его можно только разбором CSS — то есть зависимостью или
большим самописным парсером, и цена несоразмерна выгоде. Если иконки приходят из
недоверенного источника, ответ уровня платформы один: задайте CSP владельца
страницы — например, `default-src 'self'` без `'unsafe-inline'` — и держите иконки на
своём origin. Санитизация уменьшает поверхность атаки, но не заменяет CSP.

**Легаси-псевдонимы SVG 1.1 в camelCase вырезаются:** `strokeWidth`, `fillOpacity`,
`clipRule`, `stopColor`, `textAnchor`, `fontSize`, `fontFamily`, `letterSpacing`.
Причина в том, что разбор регистрозависим, а список атрибутов точен: `localName`
разобранного XML сохраняет регистр, и `strokeWidth` — уже не то же самое, что
`stroke-width`. Старый экспорт из Illustrator или Inkscape может отрендериться
неверно по толщине обводки, по наклону заливки или по якорю текста. **Симптом
молчаливый:** ничего не падает и не логируется, иконка просто выглядит не так.
Проверяйте такие файлы глазами; надёжнее — прогнать их через редактор, который
переписывает атрибуты в kebab-case.

**Атрибут `id` внутри иконки сохраняется**, и это сделано намеренно: без него `use`
и градиенты не ссылались бы сами на себя. Плата в том, что после вставки
`use href="#id"` ищет элемент во всём документе, то есть на странице-хозяине.
Идентификаторы, которые генерирует сама библиотека, начинаются с префикса `vc-`
(`vc-1-0`, `vc-1-0-sub-1`), чтобы не совпасть с чужими; **не используйте префикс
`vc-` в собственных иконках**. Свои `id` внутри иконок делайте уникальными на всю
страницу, а не только внутри иконки.

**Иконка, чей `viewBox` обрезает содержимое намеренно, будет обрезана.** Корню
принудительно выставляется `overflow="hidden"`, и это не украшение: авторский
`overflow` — presentation-атрибут, то есть источник автора, и он перебивает правило
UA-стилей, вьюпорт иконки перестаёт обрезать содержимое, а вместе с
`pointer-events` это оверлей, перехватывающий клики по меню. Ровно тот же результат
давал `style`, но без него. Если иконке нужно, чтобы содержимое выходило за
`viewBox`, отдайте это не иконкой, а отдельным элементом рядом.

**`display` и `visibility` не принуждаются.** Они разрешены, и потому
`display="none"` в вашей разметке отрисует иконку в никуда — молча, как и
`overflow` до принудительной установки. Уберите атрибут, если он не нужен.

**`filter`, `marker-*`, `pattern*`, `color-interpolation-filters` и текстовые
атрибуты разрешены, хотя соответствующие элементы в белый список не входят.**
Позиция защитная, на случай расширения списка элементов: атрибут, ссылающийся на
`filter` или на `pattern`, не должен ломаться о белый список, когда элемент туда
добавится. **Читать белый список атрибутов как обещание отрисовки нельзя** — сейчас
`filter`, `marker`, `pattern`, `text` и `tspan` в белый список элементов не входят и
вырезаются вместе с поддеревом, так что разрешённый `filter="url(#f)"` ссылается в
ничто.

### Иконки `emoji` и `raster`

`{ type: 'emoji', value: '📄' }` — символ в `span.vc-icon`, помеченный `aria-hidden`,
чтобы не дублировать озвучку лейбла.

`{ type: 'raster', value, alt }` — `img` с обязательным непустым `alt`. Принимаются
только `http:`, `https:` и `data:image/…`; остальные схемы отбрасываются, и
элемент остаётся без `src`. `alt` обязателен по контракту: пустой или
отсутствующий превращает картинку в недоступную метку, и конструктор отклоняет такую
конфигурацию.

## Запуск тестов

```bash
npm test              # весь набор: unit, chromium, firefox, webkit
npm run test:unit     # только юнит-тесты, без браузера
npm run test:e2e      # только браузерные, на трёх движках
npm run typecheck     # tsc --noEmit по src/, Demo/, scripts/ и tests/
```

Проверить, что рантайм-зависимостей нет, можно одной строкой:

```bash
node -e "const p=require('./package.json'); if (p.dependencies) { console.error('dependencies не должны существовать'); process.exit(1); } console.log('ok')"
```

В `playwright.config.js` один воркер: Firefox в параллельном режиме роняет
программный композитор, и падал бы сам движок, а не код.

Типовое окружение проверяется двумя программами подряд, и порядок обязателен:
сначала браузерная (`"types": []`, `src/**` и `Demo/**`), и только потом
node-программа (`"types": ["node"]`, `scripts/**` и `tests/**`). Node-глобал в
`src/**` или `Demo/**` ломает `npm run typecheck` именно этим порядком;
изолированный `tsc -p tsconfig.node.json` его не увидит, потому что юнит-тесты
тянут `src/**` в node-типизацию.

## Демо

```bash
npm run serve
```

Демо отдаётся на `http://127.0.0.1:4173/` (порт меняется переменной `PORT`).
Страница показывает шесть сценариев: базовое меню, вложенность, отключённые
пункты, иконки всех трёх видов, длинный список и всё вместе. Правый клик по любому
блоку сценария открывает его меню; переключатель в шапке меняет тему страницы.
