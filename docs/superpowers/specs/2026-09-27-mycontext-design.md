# MyContext — дизайн библиотеки контекстных меню

- Дата: 2026-09-27
- Статус: утверждён
- Источник: ТЗ заказчика (пункты 1–5) и 12 развилок, решённых в ходе мозгового штурма

## 1. Цель

Клиентская библиотека на чистом JavaScript (ES2026, ноль рантайм-зависимостей) для создания кастомных контекстных меню, полным визуальным и функциональным аналогом нативных системных меню: неограниченная вложенность подменю, адаптивное позиционирование в пределах экрана, системные анимации, доступность, иконки трёх типов.

## 2. Ограничения

- Рантайм-зависимостей нет вообще: поле `dependencies` в `package.json` отсутствует. Только `devDependencies` для тестов и проверки типов.
- Чистый ES-модуль, импортируется в современных браузерах без транспиляции.
- Библиотека не является глобальным перехватчиком: вне привязанного контейнера она не подавляет и не создаёт меню.
- Работа ведётся напрямую в текущей основной ветке репозитория (`master`), без feature-веток и worktree.

## 4. Архитектура

Один публичный класс и девять внутренних модулей. Границы проведены так, чтобы каждый файл можно было понять и протестировать отдельно.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `src/index.js` | Публичная точка входа, реэкспорт `MyContext` | `MyContext.js` |
| `src/MyContext.js` | Оркестратор: приватное состояние, публичный API, жизненный цикл | renderer, layer, hoverIntent, keyboard, theme, positioner |
| `src/positioner.js` | Чистая геометрия: `calculateMenuPosition`, `calculateSubmenuPosition`. Ноль DOM | — |
| `src/renderer.js` | Строит DOM уровня и пункта: сетка, колонки, разделители, шевроны | icons |
| `src/icons.js` | `renderIcon()` → `HTMLElement`. Три типа иконок + санитизация SVG | — |
| `src/layer.js` | Top Layer: создание, показ, скрытие, замер, отложенное скрытие | renderer, positioner |
| `src/hoverIntent.js` | Safe-triangle и таймер. Только геометрия траектории | — |
| `src/keyboard.js` | Роуминг-фокус, клавиши, синхронизация ARIA | — |
| `src/theme.js` | Тема и длительность анимации → CSS-переменные и `data-vc-theme` | — |
| `src/constants.js` | Числовые константы и значения опций по умолчанию | — |

Принцип декомпозиции: `positioner.js` и `hoverIntent.js` — чистые функции без побочных эффектов. Всё, что может сломаться геометрически, проверяется без браузера. Браузер нужен только для `layer.js`, `renderer.js` и сквозных сценариев.

### 4.2. Иерархия DOM уровня

```
div.vc-menu[popover=manual][role=menu]        ← Top Layer, позиционирован во вьюпорте
└── div.vc-list[role=group]                    ← flex-колонка, max-height, overflow-y: auto
    ├── div.vc-item[role=menuitem][tabindex][data-active]
    │   ├── span.vc-icon-slot                  ← ширина зарезервирована всегда
    │   ├── span.vc-label
    │   └── span.vc-chevron                    ← ширина зарезервирована всегда
    ├── div.vc-item[role=menuitem][aria-haspopup=menu][aria-expanded]
    └── div.vc-separator[role=separator]
```

## 5. Публичный API

```javascript
new MyContext(items, options)
```

- `attach(domElement)` — навесить слушатель `contextmenu` на контейнер.
- `detach()` — снять слушатель, ничего не разрушая.
- `open({ x, y })` — программное открытие в произвольных координатах.
- `close()` — закрыть все открытые уровни.
- `destroy()` — полная очистка. Идемпотентен.

### 5.1. Типы данных

```javascript
/** @typedef {{ type: 'emoji', value: string }} EmojiIconConfig */
/** @typedef {{ type: 'svg', value: string }} SvgIconConfig */
/** @typedef {{ type: 'raster', value: string, alt: string }} RasterIconConfig */
/** @typedef {EmojiIconConfig | SvgIconConfig | RasterIconConfig} IconConfig */

/**
 * @typedef {object} MenuItem
 * @property {string} [id]
 * @property {string} label
 * @property {IconConfig} [icon]
 * @property {boolean} [disabled]
 * @property {(event: MouseEvent | KeyboardEvent) => void} [action]
 * @property {MenuItem[]} [submenu]
 */

/**
 * @typedef {object} SeparatorItem
 * @property {'separator'} type
 */

/**
 * @typedef {object} MyContextOptions
 * @property {'auto' | 'light' | 'dark'} [theme]  По умолчанию 'auto'
 * @property {number} [animationDuration]          Мс, по умолчанию 140
 * @property {string} [label]                      Доступное имя меню → aria-label
 */
```

`label` добавлен сверх исходного ТЗ: `role="menu"` без доступного имени — дефект доступности, который не пройдёт аудит. Поле опционально, но без него ответственность за имя лежит на пользователе.

## 6. Жизненный цикл

### 6.1. Открытие

`attach(el)` добавляет один слушатель `contextmenu`. Обработчик вызывает `preventDefault()`, сохраняет `{x, y}` и передаёт их в `open()`.

`open({x, y})` идемпотентен: повторный вызов на уже открытом меню перепозиционирует его, не пересоздавая.

1. Ленивое построение DOM корневого уровня, если он ещё не создан.
2. Замер вслепую (см. 7.3) — получение фактических габаритов.
3. `calculateMenuPosition` → `left`, `top` в CSS-пикселях.
4. Запись координат, перенос элемента в конец `<body>` (см. 7.4), снятие маски замера.
5. `showPopover()`.
6. `focus({preventScroll: true})` на первый неотключённый пункт.

### 6.2. Открытие подменю

Наведение на пункт с `submenu` → `hoverIntent` признаёт движение не «диагональным промахиванием» → `layer.showSubmenu(item)`:

1. Ленивое построение DOM уровня, если он ещё не создан.
2. `calculateSubmenuPosition` относительно `getBoundingClientRect()` пункта-владельца.
3. **Усечение цепочки:** все уровни глубже текущего и в другой ветке скрываются. Открыли «Экспорт → PDF», навели на «Скачать» — цепочка обрезается до «Скачать».
4. `aria-expanded="true"` на пункте-владельце, перенос в конец `<body>`, `showPopover()`.
5. Фокус **не** переносится: мышь осталась в родителе, фокус живёт отдельно.

### 6.3. Закрытие

`close()`:

1. `hidePopover()` по всем элементам цепочки, от глубоких к корню, с отложенным снятием (см. 9.3).
2. Сброс `aria-expanded`, `data-active`, таймеров hover intent.
3. Возврат фокуса на элемент-владелец, иначе фокус провалится в `<body>`.
4. DOM не уничтожается — меню переиспользуется при следующем открытии. Ленивость из ТЗ (Этап 4) реализуется здесь: за время жизни строятся только реально открывавшиеся ветки.

`destroy()` снимает слушатель с контейнера, убивает таймеры, скрывает и удаляет все элементы из DOM, зануляет приватные ссылки. Повторный вызов безопасен; любой другой метод после `destroy()` бросает `Error('MyContext: экземпляр уничтожен')`.

## 7. Геометрия

### 7.1. `calculateMenuPosition`

Чистая функция. На вход `{cursorX, cursorY, menuWidth, menuHeight, viewportWidth, viewportHeight, offset, padding}`, на выход `{left, top}`.

По каждой оси независимо строится упорядоченный список кандидатов; берётся первый, помещающийся целиком. Если не помещается ни один — clamp к `padding`.

- X: `cursorX` → `cursorX - menuWidth` (флип влево) → `padding`.
- Y: `cursorY` → `cursorY - menuHeight` (флип вверх) → `padding`.

Условие «помещается» для кандидата `p` с размером `s` на оси с вьюпортом `v`: `p + s + padding <= v` и `p >= padding`.

Порядок кандидатов реализует правило «ближе к курсору побеждает», поэтому не требуется сравнивать свободное место по осям между собой. Clamp — последний рубеж, он даёт гарантию критерия 2 даже когда меню шире вьюпорта.

### 7.2. `calculateSubmenuPosition`

Чистая функция. На вход `{anchorRect, menuWidth, menuHeight, viewportWidth, viewportHeight, offset, padding}`, на выход `{left, top}`.

- **X:** предпочтительно справа, `left = anchorRect.right + offset`. Не помещается → флип влево: `left = anchorRect.left - menuWidth - offset`. Не помещается → clamp к `padding`.
- **Y:** только clamp, без флипа. `top = anchorRect.top`, затем поднять так, чтобы `top + menuHeight <= viewportHeight - padding`. Если не помещается ни сверху, ни снизу — `top = padding`, дальше работает внутренний скролл уровня.

Разница в поведении по Y не совпадение: у подменю нет собственного курсора, и нативные ОС не «выворачивают» его относительно пункта, а сдвигают, сохраняя выравнивание по верху, пока есть куда сдвигать.

У пункта, чьё подменю флипнулось по X, шеврон разворачивается: `data-chevron="left"`.

### 7.3. Замер вслепую

UA-стили задают элементу с атрибутом `popover` значение `display: none` до `showPopover()`. Наивный замер до показа даёт `0×0` и ломает всю геометрию. `layer.js` выполняет замер так: инлайново ставит `display: flex; position: fixed; left: -9999px; top: 0; visibility: hidden`, читает `getBoundingClientRect()`, записывает реальные координаты, снимает маску, вызывает `showPopover()`.

Побочного мерцания нет: на момент измерения элемент невидим, а вход через `@starting-style` начинается с `opacity: 0`.

### 7.4. Порядок отрисовки в Top Layer

Порядок отрисовки элементов Top Layer совпадает с их порядком в DOM. Поэтому перед каждым `showPopover()` элемент переносится в конец `<body>` — иначе глубоко вложенное подменю окажется под ранее созданным соседним подменю.

### 7.5. Отступ от краёв

`styles/mycontext.css` задаёт каждому уровню `max-height: calc(100dvh - 2 * var(--vc-padding))` при `--vc-padding: 8px`. JS не знает про `max-height`: он меряет уже сжатую высоту и работает с фактом. Единственное дублирование — `SAFETY_PADDING = 8` в `constants.js` для clamp-расчётов; совпадение с CSS-переменной фиксируется e2e-тестом.

## 8. Рендеринг

### 8.1. Иконки

`renderIcon(config)` возвращает элемент, готовый к вставке в слот шириной `--vc-icon-size`.

- **Эмодзи:** `<span class="vc-icon" aria-hidden="true">`. Набор `user-select: none`, `font-variant-emoji: emoji`, явный список эмодзи-шрифтов. `aria-hidden` достаточно: текст пункта уже озвучивается, дублирование не нужно.
- **SVG:** инлайн-узел с `currentColor`. Разбор через `DOMParser`, затем санитизация по белому списку элементов: `svg, path, circle, ellipse, rect, line, polyline, polygon, g, defs, use, clipPath, mask, title, linearGradient, radialGradient, stop`. Всё остальное, включая `script`, `foreignObject`, `iframe`, `image`, `style`, удаляется. Атрибуты `on*` вырезаются; `href` и `xlink:href` со схемой `javascript:` — тоже. Принудительные `width`/`height` в `100%`, `aria-hidden="true"`, `focusable="false"`.
- **Растр:** `<img class="vc-icon" alt="…" draggable="false" decoding="async">`. `alt` обязателен. Значение прогоняется через `URL`-парсер, чтобы отсечь `javascript:` и `data:text/html`.

### 8.2. Сетка пункта

CSS Grid с колонками фиксированной ширины `[--vc-icon-size] 1fr [--vc-chevron-size]`. Обе колонки зарезервированы **всегда**, на всех уровнях, независимо от наличия иконок и подменю. Это даёт соосность лейблов при любом наборе пунктов и исключает сдвиг текста при открытии подменю.

### 8.3. Соседние, а не вложенные подменю

У пункта с подменю в объекте `MenuItem` лежит поле-владелец, а сам `div.vc-menu[popover]` находится в `<body>` рядом с корневым меню, а не внутри пункта. Связь «пункт ↔ его подменю» держится полем `owner`.

Причины, по которым вложенность невозможна, идут пакетом:

- `position: absolute` внутри скроллируемого контейнера позиционируется относительно контейнера, а не вьюпорта, — подменю обрезалось бы на длинных меню;
- `backdrop-filter` на родителе создаёт containing block для потомков;
- анимация `scale` на родителе ломает координаты потомков.

Соседство снимает все три. Плата в том, что `role="menuitem"` не имеет прямого контейнера-`menu`; WAI-ARIA допускает вложенные меню отдельными `menu`, а `aria-owns` на пункте мы всё равно проставляем для скринридеров.

### 8.4. Ленивость и хранение коллбэков

Строится уровень целиком при первом открытии; следующий уровень — когда он реально показан. `action`-коллбэки извлекаются в `Map` по `id`: элементы меню не несут функций.

### 8.5. Точки входа рендерера

`renderLevel(items, context)` возвращает `LevelElement`, `renderItem(item, context)` — один `menuitem`. Оба принимают контекст с `levelIndex`, чтобы `aria-level`, `aria-setsize`, `aria-posinset` вычислялись из позиции в уровне, а не из пользовательских данных.

## 9. Взаимодействие

### 9.1. Клавиатура

Роуминг-фокус: в каждом открытом уровне ровно один пункт имеет `tabindex="0"`, остальные `tabindex="-1"`. Разделители и отключённые пункты в цикле не участвуют. Фокус ставится явно после позиционирования, а не через автофокус `showPopover()`.

| Клавиша | Поведение |
|---|---|
| `ArrowDown` / `ArrowUp` | Циклический переход по доступным пунктам уровня |
| `ArrowRight` | Открыть подменю текущего пункта, фокус в его первый пункт. Нет подменю — ничего |
| `ArrowLeft` | Закрыть текущий уровень, фокус на пункт-владелец. На корневом уровне — закрыть всё |
| `Enter` / `Space` | Активировать. У пункта-владельца активация означает открытие подменю, `action` не вызывается |
| `Escape` | Закрыть текущий уровень; на корневом — всё меню |
| `Home` / `End` | Первый / последний доступный пункт уровня |
| `Tab` | Закрыть всё меню, фокус на элемент-владелец |

Визуальное состояние активного пункта ведёт атрибут `data-active`, а не псевдокласс `:focus`: при открытии подменю мышью `:focus-visible` не сработал бы и подсветка мигнула бы. `data-active` вдобавок селекторно тестируется.

Typeahead-поиск по первым буквам не реализуется: объём кода заметно превышает заявленные требования.

### 9.2. Hover intent

`hoverIntent.js` хранит три опорные точки: точку, где курсор покинул пункт-владелец, точку, где курсор впервые вошёл в подменю, и последнюю принятую точку траектории. На каждый `pointermove` новая точка проверяется **относительно треугольника из уже принятых точек** — `[выход, вход, последняя принятая]` — и никогда не добавляется в него сама. Это обязательное требование, а не деталь реализации: если проверяемая точка одновременно является вершиной проверяемого многоугольника, она по определению лежит внутри, и проверка превращается в тождественную, то есть hover intent перестаёт работать вовсе.

Первая позиция после входа в подменю принимается без проверки и становится последней принятой. Каждая следующая проверяется против треугольника из трёх уже принятых точек. Точка вне многоугольника планирует закрытие и сбрасывает последнюю принятую на себя, поэтому следующая проверка идёт против сузившегося клина. Сброс обязателен: без него клин рос бы от каждой принятой точки, и подменю осталось бы открытым внутри всё большего треугольника.

Треугольник с площадью строго меньше `DEGENERATE_AREA` считается вырожденным, граница невырождена. Вырожденный треугольник не защищает подменю: каждая точка планирует закрытие, а последняя принятая обновляется, чтобы клин оставался вырожденным, пока курсор не вернётся ближе. Это покрывает движение почти по прямой, где ориентация не определена. Курсор вне многоугольника запускает таймер `CLOSE_GRACE_MS = 200`; возврат курсора отменяет его. Открытие другого пункта сбрасывает все три опорные точки. Точка выхода из пункта-владельца — это последняя позиция `pointermove`, зафиксированная в момент ухода курсора с пункта.

Задержка `OPEN_GRACE_MS = 250` перед открытием подменю нужна по той же причине, что и защита от ложных закрытий, только с обратной стороны: без неё подменю вспыхивает на каждом пункте, мимо которого курсор пробегает вниз по списку, — то самое дёрганье, которое запрещает критерий 3. Задержка отсчитывается от первого наведения на пункт-владелец и сбрасывается при уходе курсора. Удержание кнопки мыши у пункта-владельца открывает его подменю немедленно, минуя задержку, — как в нативных ОС.

### 9.3. Анимация входа и выхода

Вход целиком на CSS: `@starting-style` и `transition-behavior: allow-discrete` дают появление из `opacity: 0; scale(.96)` без единой строки JS.

Выход — единственное место, где JS обязан вмешаться: `hidePopover()` мгновенно убирает элемент из Top Layer, поэтому вызов откладывается на `animationDuration`, и только затем выполняется. Отсюда три обязательных правила:

- `transitionend` может не прийти при прерванном переходе или нулевой длительности, поэтому страхуем `setTimeout`;
- повторное открытие во время закрытия отменяет отложенный `hidePopover()` — иначе только что открытое меню исчезнет; отслеживается токен поколения, отложенное действие недействительно, если поколение изменилось;
- `prefers-reduced-motion: reduce` обнуляет и CSS, и JS: `layer` читает `matchMedia` в момент закрытия и пропускает отложенный `hidePopover()` целиком, иначе невидимое меню осталось бы в Top Layer и съедало бы клики по странице.

### 9.4. Разделение своего скролла и скролла страницы

Событие `scroll` не всплывает, но доходит до `window` в фазе захвата, поэтому слушатель на `window` увидит и прокрутку внутреннего списка меню. В обработчике проверяется, что цель не находится внутри `.vc-menu`; иначе меню захлопнулось бы при прокрутке длинного списка. Слушание — capture + `passive`, чтобы не блокировать скролл страницы.

### 9.5. Изоляция правого клика

Пока меню открыто, слушатель `contextmenu` на `document` глушит браузерное контекстное меню только если цель находится внутри дерева меню. Правый клик снаружи закрывает наше меню; если он попал в привязанный контейнер, его собственный обработчик тут же открывает меню заново в новой точке — так ведут себя нативные ОС. Снаружи контейнера библиотека не подавляет ничего.

### 9.6. Триггеры закрытия

Клик вне дерева меню (`pointerdown` в фазе захвата, чтобы обогнать обработчики пунктов), `Escape`, скролл страницы, `resize` окна, активация пункта.

## 10. Доступность

- `role="menu"` на каждом уровне, `aria-label` из `options.label`.
- `role="menuitem"` на пунктах; `aria-disabled` (не атрибут `disabled`, так как это не кнопки) на отключённых; `aria-haspopup="menu"` и `aria-expanded` на владельцах подменю; `aria-owns` на владельцах подменю для скринридеров.
- `role="separator"` на разделителях, `aria-orientation="horizontal"`. Разделитель не получает фокус.
- `aria-level`, `aria-setsize`, `aria-posinset` вычисляются из позиции в уровне.
- Полное управление с клавиатуры по таблице 9.1.

Два расхождения с формулировками ТЗ, оба сознательные. `aria-haspopup` выставляется значением `"menu"`, а не `"true"`: по ARIA 1.2 `true` является синонимом, но `menu` точнее и так пишут в спецификации WAI-ARIA Authoring Practices; проверка axe различает эти значения. Идентификаторы для `aria-owns` генерируются при создании уровня, так как соседние подменю не вложены в разметку пункта (8.3).

## 11. Стили

`styles/mycontext.css` — единственный источник правды по визуалу. Токены:

```
--vc-bg  --vc-bg-solid  --vc-text  --vc-muted  --vc-hover-bg  --vc-active-bg
--vc-accent  --vc-accent-text  --vc-separator  --vc-shadow
--vc-radius  --vc-padding  --vc-item-height  --vc-font  --vc-font-size
--vc-icon-size  --vc-chevron-size  --vc-animation-duration
```

**Темы.** На корневом элементе всегда стоит `data-vc-theme` со значением `auto` / `light` / `dark`. Каскад: значения светлой темы базовые; `@media (prefers-color-scheme: dark)` переопределяет их только для `[data-vc-theme="auto"]`; селектор `[data-vc-theme="dark"]` переопределяет всегда. Селектор атрибута специфичнее медиазапроса, поэтому явный `dark` побеждает системную настройку, а `auto` остаётся живым. Смена темы ОС подхватывается без перерисовки меню.

**Стекло с запасным вариантом.** Полупрозрачный фон и `backdrop-filter: blur(20px) saturate(180%)`. Чтобы в браузере без `backdrop-filter` фон не стал нечитаемым, `@supports not (backdrop-filter: blur(1px))` подставляет непрозрачный `--vc-bg-solid`. Проверяется в webkit.

**Анимации.** Вход через `@starting-style` (9.3). Выход — отложенный `hidePopover()`. `@media (prefers-reduced-motion: reduce)` обнуляет `--vc-animation-duration` и отключает `transform`.

## 12. Обработка ошибок

- **Валидация конфигурации** — в конструкторе, рекурсивно по всем уровням, чтобы битая конфигурация падала сразу, а не при первом наведении. `TypeError` с путём до узла, например `items[2].icon.type: ожидается 'emoji' | 'svg' | 'raster'`. Проверяются: непустой массив; непустая строка `label` у пункта; `action` — функция; `submenu` — массив; соответствие `icon` одному из трёх вариантов.
- **Отказ окружения.** Отсутствие `HTMLElement.prototype.showPopover` диагностируется в `attach()`, а не на импорте, чтобы `import` оставался безопасным в SSR-окружении. Сообщение называет конкретное требование.
- **Иконки — fail-soft.** Неразобранный SVG не роняет меню: в слот встаёт пустое место, в `console.warn` уходит одно предупреждение. Меню обязано работать.
- **Использование после `destroy()`** бросает `Error`. Сам `destroy()` идемпотентен.

## 13. Тестирование

Второго тестового раннера нет: всё через `@playwright/test`.

**Юнит-тесты чистых функций** (`positioner.js`, `hoverIntent.js`) — таблицы кейсов без браузера: четыре угла, крошечный вьюпорт, меню шире вьюпорта, флип подменю влево и вправо, clamp по вертикали, вырожденный треугольник, таймер. Инвариант «меню целиком внутри вьюпорта минус padding» проверяется на детерминированной сетке координат.

**Юнит-тесты в браузере** (`icons.js`, валидация конфигурации, `renderer.js`) — пустая страница, импорт модуля, прогон таблицы `renderIcon`: проверка санитизации (ни `<script>`, ни `on*` не остаётся) и равенства координат лейблов у пунктов с иконкой и без.

**E2E** (`index.html` через демо) — на трёх движках:

- открытие в каждом углу с проверкой `boundingBox()` внутри вьюпорта;
- вложенность 4 уровней без ложных закрытий;
- диагональный ховер не роняет подменю;
- полный сценарий только с клавиатуры;
- все три типа иконок и соосность лейблов;
- ПКМ по меню не открывает системное меню (`defaultPrevented === true`);
- тёмная тема через `emulateMedia`;
- `reducedMotion: 'reduce'` — меню видно сразу, без ожидания;
- после `destroy()` в DOM нет `.vc-menu` и `contextmenu` на контейнере ничего не открывает.

## 15. Критерии готовности

1. Библиотека — чистый ES-модуль, импортируется без транспиляции; в `package.json` нет поля `dependencies`.
2. Меню не выходит за видимые границы вьюпорта ни при каком расположении точки клика, включая углы и окна меньше меню.
3. Вложенные меню открываются стабильно, без дёрганий и ложных закрытий при движении мыши к ним.
4. Все три формата иконок работают; текстовые метки строго соосны независимо от наличия иконок.
5. Меню полностью функционально при использовании только клавиатуры.
6. Внешний вид соответствует нативным системным меню; анимации не блокируют взаимодействие, `prefers-reduced-motion` отключает их мгновенно.
7. `destroy()` не оставляет слушателей и DOM-узлов.

## 16. Что осознанно не входит

- Typeahead-поиск по первым буквам.
- Горячие клавиши и подписи сочетаний в пунктах меню (прямое требование ТЗ).
- `max-height` с автоподгонкой числа пунктов — вместо него внутренний скролл.
- Позиционирование через CSS Anchor Positioning: неравномерная поддержка в браузерах и прямое противоречие Этапу 3 ТЗ.
- Подавление системного контекстного меню вне привязанного контейнера.
- Сборка в единый дистрибутивный файл.
