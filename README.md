# MyContext

Контекстные меню для браузера на чистом ES-модуле. Без рантайм-зависимостей, без
сборки, с Top Layer, неограниченной вложенностью подменю и полной клавиатурной
навигацией по открытому меню.

## Возможности

- **Ноль зависимостей и ноль сборки.** В `package.json` нет поля `dependencies`, нет
  `main` и `exports`. `index.js` экспортирует ровно один символ — класс `MyContext`.
- **Меню в Top Layer.** Каждый уровень — свой элемент с `popover="manual"`, поэтому не
  перекрывается ни заголовком, ни модальным диалогом, ни `z-index` страницы.
- **Вложенность не ограничена.** Корневой уровень появляется рядом с курсором, каждый
  уровень подменю — рядом со своим пунктом-владельцем и разворачивается влево, когда
  справа не хватает места.
- **Клавиатура.** После открытия меню целиком проходится с клавиатуры, без единого
  движения мыши.
- **Длинные списки без полосы прокрутки.** Их листают колесом над списком, пальцем,
  клавишами и двумя зонами у краёв рамки.
- **Темы.** `auto` следует за системной схемой, `light` и `dark` задают её явно. Вся
  палитра — в CSS-переменных.
- **Жест удержания.** `pressAndHold` переводит меню с правого клика на удержание кнопки,
  `isArmableAction` решает по нажатию, вооружать ли жест, — раньше, чем будет построен
  корень.

## Требования

Единственное жёсткое требование — **Popover API и Top Layer**, то есть
`HTMLElement.prototype.showPopover`. Без него `attach()` бросает `Error` с названием
требования.

Базовая линия движков: Chrome и Edge 114, Firefox 125, Safari 17.

Появление и исчезновение уровней анимируются через `@starting-style` и
`transition-behavior: allow-discrete`. Это дополнительное требование: где оно не
поддержано, меню остаётся рабочим, но переходов не будет.

`prefers-reduced-motion: reduce` обрабатывается и в CSS, и в JS — см. [«Темы и
`prefers-reduced-motion`»](#темы-и-prefers-reduced-motion).

## Установка

```bash
npm install
```

Зависимости нужны только для разработки: Playwright, TypeScript и типы Node. Подключение
состоит из двух файлов:

```html
<link rel="stylesheet" href="./styles/mycontext.css" />
<script type="module">
  import { MyContext } from './src/index.js';
</script>
```

Таблицу стилей подключать обязательно: в ней лежат геометрия, палитра и анимации. Без
неё меню откроется, но не будет выглядеть меню.

Модуль обязательно должен отдаваться по `http(s)`, а не с `file://`: браузер запрещает
загрузку ES-модулей с файловой системы. Штатный способ — `npm run serve`, он же
поднимает демо.

## Быстрый старт

```js
import { MyContext } from './src/index.js';

const menu = new MyContext(
  [
    {
      labelAction: () => 'Открыть',
      iconAction: () => ({ type: 'emoji', value: '📂' }),
      action: () => console.log('открыть'),
      submenuAction: () => [
        { labelAction: () => 'Недавние', action: () => console.log('недавние') },
        {
          labelAction: () => 'Проект',
          submenuAction: () => [
            { labelAction: () => 'Черновик', action: () => console.log('черновик') },
            { labelAction: () => 'Готово', action: () => console.log('готово') },
          ],
        },
      ],
    },
    { type: 'separator' },
    {
      labelAction: () => 'Вставить картинку',
      iconAction: () => ({ type: 'raster', value: '/icons/picture.png', alt: 'Картинка' }),
      action: () => console.log('вставить'),
    },
  ],
  { label: 'Меню файла', theme: 'auto' },
);

menu.attach(document.querySelector('#workspace'));
```

`attach` подписывается ровно на одно событие — `contextmenu` на переданном контейнере, и
подавляет системное меню внутри него. **Открывается меню правым кликом по контейнеру.**

Единственный программный путь — `open({ x, y })`, и он же нужен для «меню по кнопке»:

```js
document.querySelector('#paste').addEventListener('click', (event) => {
  menu.open({ x: event.clientX, y: event.clientY });
});
```

**Клавиатурного способа открыть меню через API нет** — добавьте триггер сами, см.
[«Открытие без привязки»](#открытие-без-привязки).

## Публичный API

### `new MyContext(items, options?)`

Создаёт меню. Форма конфигурации проверяется сразу: бросается `TypeError`, а в сообщении
назван путь до поля (`items[1].labelAction`). Слушателей на страницу конструктор не
вешает. Пустой корневой массив отклоняется.

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `theme` | `'auto' \| 'light' \| 'dark'` | `'auto'` | оформление всех уровней |
| `animationDuration` | `number`, мс | `140` | вход, выход и задержка отложенного закрытия |
| `label` | `string` | `'Меню'` | доступное имя меню, ставится каждому уровню |
| `autoHideDistance` | `number`, px | `0` | на каком расстоянии от показанных уровней меню прячется само; `0` — никогда |
| `scale` | `number` | `1` | множитель всех длин меню на каждом уровне; больше и меньше единицы |
| `pressAndHold` | `'none' \| 'left' \| 'right' \| 'middle' \| 'any'` | `'none'` | какой кнопкой меню открывается и когда закрывается; `'none'` — показ по правому клику |
| `isArmableAction` | `(event: PointerEvent) => boolean \| Promise<boolean>` | — | разрешать ли нажатие вооружать жест; ответ не из `true` оставляет меню закрытым |
| `destroyOnClose` | `boolean` | `false` | разбирать ли экземпляр при закрытии; меню, заведённое на один показ |

`animationDuration` управляет всеми тремя местами сразу. Ополя проверяются по форме, и
каждое значение вне перечисленного отклоняется, включая пустой `label`, нулевой и
нечисловой `scale`.

Проверяется только корневой состав: значения читающих действий известны на показе, и до
показа их нет. Подпись, иконку и состав подменю проверяет рендерер при сборке уровня, и об
ошибке сообщает `open()`, а не конструктор.

Неочевидные опции разобраны ниже — в разделе [«Опции»](#опции).

### Пункт меню

Подпись, иконка и подменю заданы **действиями, а не значениями**: они нужны на показе, и
раньше показа их не существует.

| Поле | Тип | Обязательность |
| --- | --- | --- |
| `labelAction` | `() => string \| Promise<string>` | обязательно; вернул не строку или пустую — `TypeError` |
| `id` | `string` | необязательно, копируется в `data-id` и в ключ пункта не входит |
| `iconAction` | `() => IconConfig \| Promise<IconConfig>` | необязательно; вернул не описание иконки — `TypeError`. Без него слот остаётся пустым, но занимает место |
| `action` | `(event) => void \| Promise<void>` | необязательно; вызывается по клику и по `Enter`/`Space`, в том числе у пункта-владельца непустым подменю |
| `isEnabledAction` | `() => boolean \| Promise<boolean>` | необязательно; зовётся при каждом показе меню, ответ не из `true` отключает пункт |
| `submenuAction` | `() => MenuItem[] \| Promise<MenuItem[]>` | необязательно; вернул не массив или пустой — `TypeError`. Непустой массив и доступность по `isEnabledAction` делают пункт владельцем |
| `handoffAction` | `(event: Event, handoff: SubmenuHandoff) => void \| Promise<void>` | необязательно; не функция — `TypeError`. Вместе с доступностью делает пункт отдающим управление; см. ниже |
| `focusAction` | `() => void \| Promise<void>` | необязательно; зовётся, когда пункт получает фокус |
| `blurAction` | `() => void \| Promise<void>` | необязательно; зовётся, когда пункт теряет фокус |
| `version` | `number` | необязательно, `0` по умолчанию; см. ниже |

**Разделитель** — это `{ type: 'separator' }`. Имя `type` обязано быть ровно
`'separator'`, любое другое значение бросает `TypeError`; лишние поля просто игнорируются.

**Пустое подменю — ошибка**, а не «не подменю».

Ушедшие из контракта поля `label`, `icon`, `submenu` и `disabled` больше не принимаются:
конструктор бросает на каждом из них `TypeError`.

#### Действия и показ

Читающие действия (`labelAction`, `iconAction`, `submenuAction`, `isEnabledAction`)
вызываются заново при **каждом** показе, а не один раз при создании экземпляра:

```js
{
  // Показ открывает новый документ — подпись узнаёт об этом сама.
  labelAction: () => (document.hidden ? 'Показать' : 'Скрыть'),
  isEnabledAction: () => clipboard.length > 1,
  submenuAction: () => [
    { labelAction: () => 'В один' },
    { labelAction: () => 'В новый' },
  ],
}
```

**Любое из них может вернуть промис.** Меню ждёт обещания и показывается, когда данные
готовы; читающие действия собираются параллельно. Синхронный ответ и промис равноправны.

Нарушение формы бросает `TypeError` из `open()` с путём до поля вида
`vc-3-0:2.labelAction`.

**Отказ читающего действия — отказ самого `open()`**: отказ летит из промиса `open()`, и
подписчик `error` его не отменяет. Меню при этом не показывается вовсе. Отказ `action`,
`handoffAction`, `focusAction`, `blurAction` и подписчиков событий ждать некому — они
приходят событием `error`.

`action` получает настоящее событие активации с настоящей целью. Отказ разбирается
событием `error`, а меню закрывается в `finally` — кроме случая, когда действие само
вызвало `open()`: тогда закрытие пропускается.

#### `isEnabledAction`

Единственный источник доступности пункта. Предикат не принимает аргументов, возвращает
`boolean`; без поля пункт доступен. Сравнение строгое, `=== true`.

Ответ не из `true` отключает пункт: он не входит в цикл клавиатурной навигации, мышью по
нему не попасть, его действие не зовётся. Непустое подменю у отключённого пункта не делает
его владельцем — шеврона и `aria-haspopup` у него не будет.

#### Владелец подменю со своим действием

У пункта-владельца подменю может быть **и** `submenuAction`, **и** `action`. Тогда он
активируется как обычный пункт — по клику, `Enter`/`Space` и отпусканию под
`pressAndHold`: действие зовётся и всё меню закрывается.

```js
{
  labelAction: () => 'Обновить',
  action: () => reload(),
  submenuAction: () => [
    { labelAction: () => 'Перезагрузить' },
    { labelAction: () => 'Обновить из сети' },
  ],
}
```

Раскрытие никуда не девается: шеврон, `aria-haspopup`, `aria-owns` и заведённый уровень
остаются как были, наведение раскрывает подменю, и `ArrowRight` входит в него. Владелец
**без** `action` ведёт себя как раньше: клик и `Enter`/`Space` раскрывают подменю.

Отдача управления имеет приоритет: у пункта с `handoffAction` клик уводит чужое меню, а
своё `action` не зовётся.

#### `focusAction` и `blurAction`

Оба зовутся одинаково для обычного пункта и пункта-владельца, одинаково для мыши и
клавиатуры. Аргументов обычно не принимают: пункт автору и так известен по замыканию.

```js
{
  labelAction: () => 'Документы',
  submenuAction: () => list(),
  focusAction: () => showPreview(list()),
  blurAction: () => hidePreview(),
}
```

| Действие | Когда зовётся |
| --- | --- |
| `focusAction` | курсор встал на пункт, стрелка сдвинула выделение на него, `ArrowRight` увёл фокус в первый пункт его подменю |
| `blurAction` | выделение ушло соседу, курсор покинул дерево меню, `ArrowLeft` вернул фокус владельцу, меню закрылось, пункт исчез вместе со своим уровнем |

**Подсветка и фокус — разные вещи.** `ArrowRight` на пункте-владельце оставляет его
выделенным и уводит фокус в подменю: `blurAction` приходит в этот момент, и читать его
надо как «фокус ушёл с меня», а не как «меня сняли с выделения».

**Пара всегда полная.** Сколько раз пришло `focusAction`, столько же раз придёт
`blurAction`, и не позже закрытия меню. Разделитель событий не получает никогда.

Оба события приходят в том же стеке, что и перемена состояния, и оба могут вернуть промис.
**Порядок завершения промисов не гарантируется.** Отказ приходит событием `error` и
ничего не отменяет.

**Предел: чужой код, уведящий фокус с пункта.** Библиотека узнаёт о передаче фокуса только
из своих собственных перемещений. Если фокус уведёт чужой обработчик — вызовет `.focus()`
на своей форме, — `blurAction` придёт только при следующей передаче фокуса или при
закрытии.

#### `handoffAction`

Передаёт управление **наружу**: что и где показать, решает автор, а меню обязано только
уйти с экрана.

```js
const owner = new ForeignMenu({ items: [{ /* … */ }] });

const menu = new MyContext([
  {
    labelAction: () => 'Цвет',
    handoffAction: (event, handoff) => {
      owner.openSubmenu(event.clientX, event.clientY, handoff);
    },
  },
]);
```

Второй аргумент — описание живого жеста в той же форме, которую соседнее меню принимает
третьим аргументом `openSubmenu`:

| Поле | Что значит |
| --- | --- |
| `held` | Кнопка зажата прямо сейчас. `true` на удержании, `false` по клику и с клавиатуры. |
| `button` | Какая кнопка держит жест. `null` — не названа: так при `pressAndHold: 'any'` с внешним вооружением. При `held: false` поле справочное. |

Правила:

- **Срабатывает по всем путям активации**: наведение с задержкой как у владельца
  подменю, нажатие — без неё, клик, `Enter` и `Space`.
- **Меню уходит безусловно и до вызова действия.** Порядок виден и снаружи: событие
  `close` нашего меню приходит раньше события `open` чужого.
- **Действие зовётся один раз на показ**, хотя активация даёт три события: наведение
  планирует показ, нажатие показывает немедленно, `click` приходит следом.
- **Владельцем подменю пункт не становится**: шеврон и `aria-haspopup` ему полагаются, а
  `aria-owns` — нет. Отключённый пункт не отдаёт.

Отказ разбирается событием `error`; отменённое отдачу повторно не зовут.

Событие активации достаётся как есть: по наведению это `pointerenter`, по нажатию
`pointerdown`, с клавиатуры `keydown`. На клавиатуре координат у события нет вовсе, поэтому
по клавиатуре сабменю открыть нельзя: отдача сработает, а открывать будет нечем.

#### `version` и состав уровня

Состав уровня задаётся значениями, а не ссылками: автор вправе отдать на каждом показе
новый массив новых пунктов. Перед показом состав сверяется по **отпечатку** — длина,
порядок, разделители, значения `id` и `version`.

- **отпечаток совпал** — уровень не перестраивается, обновляются только ответы действий;
- **разошёлся** — уровень перестраивается целиком вместе со всем, что из него открыто, под
  тем же `id`.

Запись пункта в карте действий перезаписывается всё равно: по клику зовётся действие
нового пункта.

Отпечаток не различает новые объекты, и это правильно: подпись, иконка и подменю у них и
так перечитываются. Когда этого мало, есть `version` — он входит в отпечаток, и его
подъём заставляет уровень перестроиться при неизменившейся структуре.

```js
{
  labelAction: () => 'Формат',
  submenuAction: () => clipboardFormats().map((format) => {
    return { labelAction: () => format.name, action: () => paste(format) };
  }),
  version: 2,
}
```

`version` — необязательное конечное число, `0` по умолчанию, не-число отклоняется.

### Методы

| Метод | Принимает | Возвращает | Бросает |
| --- | --- | --- | --- |
| `attach(element)` | контейнер, на котором ловится `contextmenu` | — | `Error` |
| `detach()` | — | — | `Error` |
| `open({ x, y }, options?)` | координаты вьюпорта, px | `Promise<void>` | `Error`, `TypeError` |
| `openSubmenu(x, y, handoff?)` | координаты вьюпорта, описание живого жеста | `Promise<void>` | `Error`, `TypeError` |
| `openAsSubmenu(x, y)` | координаты вьюпорта, px | `Promise<void>` | `Error`, `TypeError` |
| `close()` | — | — | `Error` |
| `destroy()` | — | — | — |
| `MyContext.closeAll()` | — | — | — |

Координаты везде — координаты вьюпорта в пикселях.

**Разбор: `open()` возвращает промис.** Меню с синхронными действиями показывается до
следующего кадра, но обещать этого нельзя: те же действия могут вернуть промис, и тогда
показ случится, когда данные готовы. Промис разрешается после показа и отклоняется отказом
читающего действия. Отмена показа закрытием или другим показом отказом не является. Вызывающий,
которому важен момент показа, ждёт его:

```js
await menu.open({ x: 200, y: 300 });
```

Проверки, не зависящие от данных пункта, бросают **синхронно**, а не отказом промиса:
уничтоженный экземпляр и нелогическая опция. Ловите их `try/catch` вокруг самого вызова,
а не `.catch()` промиса: тот увидел бы только отказ читающего действия. Требование
[Popover API](#требования) проверяется только в [`attach()`](#attachelement) — `open()`
без привязки ею не пользуется.

| Поле `options` | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `armed` | `boolean` | `false` | показать меню внутри уже начатого жеста удержания |
| `dismissible` | `boolean` | `false` | поднять на время показа глобальные правила закрытия |

Повторный `open()` по открытому меню идёт обычным циклом: уровни гаснут на месте, корневой
показывается в новой точке. Уровень и его пункты не пересоздаются, второго меню не
заводится. Фокус встаёт на элемент уровня, а не на пункт: выделения после открытия нет,
и первую же стрелку разбирает меню.

#### `attach(element)`

Подписывает контейнер на `contextmenu` и вешает глобальные слушатели закрытия. Повторный
вызов переносит привязку: предыдущий контейнер освобождается.

Бросает `Error`, если экземпляр уничтожен или браузер не умеет Popover API. Требование
проверяется здесь, а не в конструкторе: без привязки экземпляр пригоден для `open()`.

#### `detach()`

Снимает подписку с контейнера, ничего не разрушая: экземпляр остаётся пригодным для
`open()`. Вызов без привязки — не операция. Снимает глобальные слушатели закрытия, а не
только привязку: показанное меню останется на экране, но гасить его будет нечем, кроме
`Escape` и `close()`.

#### `options.armed`

```js
menu.open({ x: 200, y: 300 }, { armed: true });
```

Покрывает случай, когда **кнопку держит вызывающий код, а меню он открывает уже после
нажатия**: нажатия по контейнеру у такого меню не было, вооружения нет, и разбирать
отпускание некому.

Кнопка, названная `options.pressAndHold`, считается уже зажатой (при `'any'` — любая).
Жест вооружается по кнопке, а не по указателю. Привязка не требуется, подписка снимается
вместе с жестом. Остальное меню не меняется.

Требует `pressAndHold`, отличного от `'none'`, иначе `TypeError`. Не-логическое значение
`armed` — тоже `TypeError`.

**Цикл удержания живёт внутри одного экземпляра.** Правый клик по блоку другого экземпляра
гасит чужое меню на месте и открывает своё в том же такте, кросс-фейдом.

#### `options.dismissible`

```js
menu.open({ x: 200, y: 300 }, { dismissible: true });
```

Показ, за который отвечает чужой код: пункт другого меню, кнопка на странице, чужой
обработчик.

- **Правила те же, что у привязанного экземпляра, — целиком.**
- **Подписка живёт до закрытия, а не до конца вызова**, поэтому экземпляр, заводимый на
  каждый показ, ими не течёт. У привязанного экземпляра опция ничего не меняет.
- **Показ не изменился:** нового способа открыть меню опция не вводит.
- **`detach()` во время такого показа правила снимает.**

Не-логическое значение бросает `TypeError`.

#### `openSubmenu(x, y, handoff?)`

Показ как сабменю чужого меню, которое зовёт `openSubmenu(x, y, handoff)`. Ради этого
метода существует поле `menu` в пункте чужого меню: туда кладётся **сам экземпляр**, без
обёртки.

```js
// То, что кладётся в пункт чужого меню.
const someMyContext = new MyContext(items, { pressAndHold: 'right' });

// Соседнее меню по показу зовёт openSubmenu(x, y, handoff).
const owner = new ForeignMenu({ items: [{ /* … */, menu: someMyContext }] });
```

```ts
type SubmenuHandoff = {
  button: 'left' | 'middle' | 'right' | 'back' | 'forward' | null;
  held: boolean;
};
```

- **`held: true` вооружает жест удержания на показе:** отпускание этой кнопки закрывает
  меню, а если под курсором доступный пункт — ещё и исполняет его действие.
- **Кнопка приходит из `handoff`, а не из пресета.** Пресет отвечает на вопрос «какой
  кнопкой это меню открывают», handoff — «какой кнопкой его открыли сейчас».
- **Политика показа ребёнка от handoff не меняется** — передаётся жест, а не политика.
- **Правила закрытия поднимаются на время показа**, и с ними начинает работать
  `autoHideDistance`.

| Условие | Результат |
| --- | --- |
| `handoff` не задан | показ без жеста, без ошибки |
| `handoff` не объект, `held` не `boolean` | `TypeError` |
| `held === false` | показ без жеста; `button` читается, но на показ не влияет |
| `held === true`, `button` — известное имя | жест удержания на этой кнопке |
| `held === true`, `button === null` | жест удержания на любую кнопку |
| `held === true`, неизвестное имя кнопки | `TypeError` |
| `held === true` при `pressAndHold: 'none'` | `TypeError` |

Возвращает `Promise<void>`, как и `open`. Отличается только тем, что поднимает правила
закрытия и вооружает жест из описания.

Что стоит знать:

- **Кто закрывает переданное сабменю.** Его собственный проект: `MyContext.closeAll()` не
  трогает соседний пакет, а `closeAll()` соседнего — `MyContext`. Общего реестра у
  независимых пакетов нет.
- **Призрак уходящего меню.** Уровень `MyContext` гаснет в Top Layer, а меню соседнего
  пакета живёт в обычном потоке, поэтому примерно на `animationDuration` после передачи
  видно призрак. На работу не влияет.
- **Повторный вызов идёт обычным циклом `open()`:** уровни гаснут на месте, корневой
  показывается в новой точке через `animationDuration`. Меню, которое открывают на каждый
  сектор удержания, перерисовывается на каждом переходе — это цена показа из чужого кода,
  а не особенность метода.
- **Действие пункта не должно звать меню обратно.** Отпускание закрывает меню раньше, чем
  зовёт действие, а с `destroyOnClose` — ещё и разбирает экземпляр. `open()` или `close()`
  изнутри `action` бросят `Error`. Путь клика ограничения не имеет.

#### `openAsSubmenu(x, y)`

Частный случай `openSubmenu`: жест объявляется живым, а кнопкой считается та, которую
называет `pressAndHold`.

```js
// Оба показа в одной точке: первое без handoff, второе с живым жестом на пресете.
someMyContext.openSubmenu(300, 200);
someMyContext.openAsSubmenu(300, 200);
```

При `'any'` кнопка не называется и жест вооружается на любую. При `'none'` бросает
`TypeError`. Возвращает `Promise<void>`.

#### `close()`

Закрывает всю цепочку уровней от глубоких к корню, отменяет отложенные открытия и
возвращает фокус привязанному контейнеру. Без привязки фокус возвращать некуда, и вызов
просто скрывает. Повторный вызов безопасен.

У экземпляра с `destroyOnClose` этот вызов — и любое другое закрытие — разбирает его
целиком, так что следующий `close()` бросит `Error`.

#### `destroy()`

Снимает все подписки и висящие задачи, удаляет все уровни из DOM и очищает внутреннее
состояние.

**`destroy()` не шлёт событий.** Он снимает экран вместе с меню — зовите `close()` перед
ним, иначе подписчик получит `close`, которому не предшествовало `open`.

**Идемпотентен, а остальные методы после него бросают `Error`** с сообщением
`MyContext: экземпляр уничтожен`.

Меню, заведённое на один показ, звать это вручную не нужно: у него есть
`destroyOnClose`.

#### `MyContext.closeAll()`

Статический метод. Закрывает меню **всех живых экземпляров** на странице. Для
приложения, у которого нет ссылок на экземпляры: смена маршрута, открытое модальное
окно, `Escape` на документе.

```js
document.addEventListener('routechange', () => {
  MyContext.closeAll();
});
```

- **Экземпляры не разрушаются** — кроме случая `destroyOnClose`, где разбор объявлен
  частью закрытия.
- **Фокус не возвращается:** у каждого экземпляра свой контейнер, и при нескольких меню
  контейнеры конкурируют.
- **Отложенный показ переоткрытия снимается.**
- **Уничтоженные экземпляры не трогаются** — `destroy()` убирает экземпляр из реестра живых.
- **Возвращаемого значения нет.**

### События

Экземпляр — `EventTarget`. Подписаться можно когда угодно, в том числе после `open()`.

```js
menu.addEventListener('open', (event) => {
  console.log('меню показалось в', event.detail.x, event.detail.y);
});

menu.addEventListener('close', () => {
  console.log('меню ушло с экрана');
});
```

| Событие | Когда | `detail` |
|---|---|---|
| `open` | корневой уровень показан | `{ x, y }` — точка вызова в координатах вьюпорта, px |
| `close` | меню ушло с экрана | пуст |
| `error` | отказ действия, ждать которого некому | `{ reason, source }`; отменяемо, см. ниже |

События не всплывают и не отменяются: `event.preventDefault()` на `open` и `close` ничего
не значит. `addEventListener` и `removeEventListener` перегружены по имени события, поэтому
`event.detail` приходит нужного типа и **писать приведения не нужно**.

**Подписчик может быть асинхронным.** Возвращённый им промис ждёт библиотека. Отказ из
подписчика приходит событием `error` с `source` вида `` `${type}:listener` ``, то есть
`'open:listener'`. Одна и та же функция, подписанная дважды на одно событие, зовётся один
раз.

#### Отказы: событие `error`

Отказ `action`, `handoffAction`, `focusAction`, `blurAction`, `isArmableAction` и
подписчиков событий приходит сюда:

```js
menu.addEventListener('error', (event) => {
  console.warn(event.detail.source, event.detail.reason);
  if (event.detail.source === 'action') {
    event.preventDefault(); // этот отказ для приложения ничего не значит
  }
});
```

| Поле `detail` | Что значит |
| --- | --- |
| `reason` | отказ как его бросил автор: `Error`, строка или что угодно |
| `source` | имя авторской точки входа, отказ которой пришёл |

`source` — либо имя поля пункта (`'action'`, `'handoffAction'`, `'focusAction'`,
`'blurAction'`, `'isArmableAction'`), либо `` `${type}:listener` `` для подписчика, либо
`'open()'`.

Событие **отменяемо**: подписчик, зовёт `preventDefault()`, отменяет отказ целиком.
**Неотменённый отказ уходит на страницу как непойманная ошибка**, и её видит
`window.onerror`.

Отказ **читающего** действия сюда не попадает: его ждёт вызывающий `open()`, и он приходит
отказом промиса.

Точка в `detail` — та же, что автор передал в `open({ x, y })`.

**Оба события приходят синхронно, в том же стеке, что и действие меню.** `open`
объявляется после `showPopover`, `close` — после снятия уровней и возврата фокуса. Отказ,
брошенный из обработчика, не прерывает ни показ, ни закрытие.

Чего событий **нет**:

- **Подменю.** Показ и скрытие уровня-подменю событий не порождают. Корневой уровень —
  единственный, кто говорит.
- **`close` на закрытом меню.** Событие приходит только если меню правда показывалось.
- **`close` из `destroy()`.**
- **Промежуточных показов при переоткрытии.** Повторный `open()` приходит вторым `open`,
  и `close` между ними не бывает: обработчик `open` обязан быть идемпотентным.

У экземпляра с `destroyOnClose` `close` приходит **до** разбора: в обработчике экземпляр
ещё жив. В пути `handoffAction` порядок задан: наше `close` раньше `open` чужого меню.

## Опции

Разбор опций, которые чаще всего требуют объяснения. Полный список полей — в таблице
[`new MyContext`](#new-mycontextitems-options).

### `autoHideDistance`

```js
const menu = new MyContext(items, { autoHideDistance: 120 });
```

Расстояние считается от **края прямоугольника** до курсора, внутри прямоугольника оно
нулевое. Меню прячется, когда курсор отошёл дальше порога **от всех** показанных уровней
сразу, то есть проверяется расстояние до ближайшего из них. Открытое подменю продлевает
зону: уход в его сторону — это не уход из меню.

- **Ноль — это «выключено».** Порог меньше расстояния между уровнями или высоты пункта
  закрывал бы меню на пути к подменю.
- **Предыстории у правила нет.** Меню, открытое программно в стороне от курсора,
  спрячется по первому же движению мыши. Если это не устраивает — оставьте `0` и закрывайте
  сами.
- **Закрытие возвращает фокус** привязанному контейнеру. Клик по странице, скролл и
  `resize` фокус не возвращают.
- **Живёт на своём слушателе движения**, а общий список `dismissible` его не дублирует.
- **Правило одинаково для мыши, пера и касания.**

### `scale`

```js
const menu = new MyContext(items, { scale: 1.5 });
```

Множитель размеров меню. По умолчанию `1`. Умножается всё, из чего меню построено: высота
пункта, кегль, иконки, шевроны, отступы, скругления, рамка, разделители и зоны прокрутки.
Множитель пишется на **каждый** уровень, поэтому подменю масштабируется тем же и остаётся
согласованным с корнем.

Значение задаётся один раз, в конструкторе, и сменить его на лету нельзя — пересоздайте
экземпляр.

- **Значения меньше единицы уменьшают меню** — это заявленный случай, а не поломка.
- **Требуется конечное число строго больше нуля.**
- **Верхней границы нет.** Меню не выйдет за вьюпорт; большое значение означает длинный
  список, а поломку.
- **Зазоры позиционирования не растут.**
- **Анимация входа не участвует:** появление остаётся `scale(0.96) → scale(1)`.
- **Множитель занят ровно один — `--vc-scale`**, и он переопределяет вашу таблицу стилей
  инлайном на каждом уровне.

### `pressAndHold`

```js
const menu = new MyContext(items, { pressAndHold: 'left' });
```

Переводит меню с правого клика на удержание кнопки. Значение называет кнопку, а не
включает жест: `'none'` — прежнее поведение, `'left'`, `'right'`, `'middle'` — своя
кнопка, `'any'` — любая из них.

Жизненный цикл целиком:

- **Нажатие показывает меню в точке нажатия** — сразу же.
- **Отпускание закрывает меню всегда.** Никакого таймера.
- **Отпускание над доступным пунктом исполняет его действие.** Порядок один на все пути
  активации: сначала закрытие, потом действие, чтобы открытое им заново меню не убивалось
  закрытием. Пункт ищется до закрытия, потому что с `destroyOnClose` закрытие стирает карту
  действий.
- **Действие не должно звать меню обратно.** С `destroyOnClose` экземпляр к моменту
  действия уже разобран: `open()` или `close()` изнутри `action` бросят `Error`.
- **Фокус после отпускания над пунктом возвращается** контейнеру, после отпускания мимо
  пунктов — нет.
- **Отпускание над всем остальным закрывает молча:** над отключённым пунктом, разделителем,
  полями каркаса, зоной прокрутки и пустотой страницы. Над пунктом-владельцем подменю —
  тоже молча, если своего `action` у него нет.
- **Нажатие любой другой кнопкой во время удержания закрывает меню** независимо от того,
  где пришлось.

Что стоит знать:

- **Правый клик перестаёт открывать меню** — `contextmenu` больше не показывает его.
  Системное меню браузера на привязанном контейнере по-прежнему гасится.
- **Наведение во время удержания работает как обычно**, поэтому до пункта подменю можно
  дойти, не отпуская кнопку.
- **Жест снимается любым закрытием**, а не только отпусканием.
- **Нажатие гасит выделение текста и нативное перетаскивание.** Фокусу вреда нет.
- **Программный `open()` под опцией не меняется** — новый цикл принадлежит жесту, а не
  экземпляру.
- **Работает только у привязанного экземпляра.**
- **Значение задаётся на всё время жизни меню** и не переключается на показ.

### `isArmableAction`

```js
const menu = new MyContext(items, {
  pressAndHold: 'right',
  isArmableAction: (event) => event.target.closest('.photo') !== null,
});
```

Предикат, решающий, вооружать ли нажатие жест удержания. Зовётся на каждом нажатии
подходящей кнопки и получает живой `PointerEvent` этого нажатия. Ответ не из `true`
оставляет меню закрытым, и жест не вооружается.

**Ответом может быть промис.** Тогда решение о `pressAndHold: 'left'` принимается
синхронно, а меню показывается, когда предикат ответит:

```js
const menu = new MyContext(items, {
  pressAndHold: 'left',
  isArmableAction: async (event) => (await isEditable(event.target)) === true,
});
```

**Плата за асинхронный предикат при `pressAndHold: 'left'`: выделение текста подавляется
на каждом нажатии**, включая те, где предикат ответит `false`. С `'right'` и `'any'`
вопросов нет.

Предикат движет решение до показа — именно для этого он и нужен. Подписи, иконки и
доступность читаются при показе, то есть уже после нажатия, а без предиката хост,
решающий по нажатию, узнаёт о цели слишком поздно:

```js
// Идентификатор жатого элемента становится известен до того, как построен корень.
let currentId = null;
const menu = new MyContext(items, {
  pressAndHold: 'right',
  isArmableAction: (event) => {
    const hit = event.target.closest('.photo');
    if (hit === null) return false;
    currentId = hit.dataset.id;
    return true;
  },
});
```

Что стоит знать:

- **Предикат зовётся последним из проверок нажатия** — после кнопки, контейнера и
  «не внутри самого меню».
- **Сравнение строгое, `=== true`.** Как у `isEnabledAction`.
- **Осмысленна только при `pressAndHold`, отличном от `'none'`:** при `'none'` не зовётся
  вовсе.
- **Отказ не открывает меню**, снимает вооружение и приходит событием `error`.
- **С несколькими меню на одном контейнере предикат и есть маршрутизация:** у
  `pressAndHold` нет выбора режима, какой есть у `contextmenu`, поэтому у каждого
  экземпляра предикат свой.

### `destroyOnClose`

```js
// Обработчик, который сам же показывает меню, и есть тот, кто его заводит.
element.addEventListener('contextmenu', (event) => {
  event.preventDefault();
  const menu = new MyContext(items, { destroyOnClose: true });
  menu.attach(element);
  menu.open({ x: event.clientX, y: event.clientY });
});
```

Меню, заведённое на один показ, само себя убирает: ссылки на него нет ни у кого, кроме
обработчика, а к следующему показу её там уже не будет. Между показами экземпляр держал бы
на странице слушатель `contextmenu`, глобальные правила закрытия, уровни в DOM и запись в
реестре живых.

При закрытии:

- **Разбирается всё сразу: подписки, задачи, карты, реестр** — в том же такте, что и
  закрытие.
- **Экземпляр объявляется уничтоженным сразу:** `open`, `attach`, `detach` и `close`
  бросают `Error`, `destroy()` остаётся идемпотентным.
- **Контейнер перестаёт открывать меню.** Мёртвый экземпляр на клик не отвечает вовсе, а не
  бросает из обработчика.
- **Уровни снимаются в конце анимации выхода**, а не сразу. Под `reduce` выхода нет, и разбор
  мгновенен.

Что стоит знать:

- **Разбор на любом закрытии** — клик по пункту, `Escape`, клик вне, прокрутка, `resize`,
  уход вкладки в фон, потеря фокуса окна, `autoHideDistance`, `close()`, `closeAll()`.
- **Закрытие подменю закрытием меню не считается:** следующий `Escape` закрывает корень и
  разбирает экземпляр.
- **Переоткрытие на месте тоже не закрытие** — это тот же показ.
- **Одноразовый экземпляр нельзя воскресить.** Если меню нужно открывать снова — не задавайте
  опцию.
- **Ссылка на экземпляр после закрытия мёртвая:** из неё можно звать только `destroy()`.

## Клавиатура

Внутри открытого меню клавиатура работает полностью:

| Клавиша | Действие |
| --- | --- |
| `ArrowDown` / `ArrowUp` | следующий / предыдущий доступный пункт, по кругу |
| `Home` / `End` | первый / последний доступный пункт |
| `ArrowRight` | открыть подменю пункта-владельца и перейти в него; подменю с асинхронным составом открывается, когда данные готовы |
| `ArrowLeft` | закрыть текущий уровень и вернуться на пункт-владелец |
| `Enter` / `Space` | вызвать действие пункта и закрыть меню; у пункта-владельца без своего действия — открыть подменю; без выделенного пункта ничего не делает |
| `Escape` | закрыть текущий уровень; на корневом — всё меню |
| `Tab` | закрыть меню и вернуть фокус контейнеру |

**Раскрытие с клавиатуры ждёт данных владельца:** при асинхронном `submenuAction` перенос
фокуса происходит после ответа. Клавиша при этом гасится сразу. `ArrowRight` открывает
подменю у любого владельца, в том числе у объявившего своё `action`.

Клавиша достаётся не тому уровню, где стоит фокус, а **текущему** — самому глубокому из
открытых. Перемещение и уход достаются текущему уровню, а раскрытие и активация остаются
на уровне, из которого пришла клавиша. `Tab` уровней не знает: он всегда закрывает всё
меню.

Разделители и отключённые пункты в цикл навигации не входят и подсветки не получают.
Выделения сразу после открытия нет, а признак выделения один: заливка активного пункта —
кольца фокуса нет ни на пункте, ни на уровне.

**Подменю открыто, пока выделен его владелец, а не пока курсор рядом.** Пока выделен
пункт `A`, его подменю открыто; переход на соседний пункт того же уровня закрывает его —
у соседа с подменю открывается подменю соседа, у соседа без подменю остаётся выделенным
только сосед. Возврат курсора на владельца уже открытого подменю не меняет ничего.

**Уход курсора подменю не закрывает.** Зона прокрутки, поля меню, разделитель и пустота
страницы — всё это нейтральные области: подменю остаётся открытым, пока выделен владелец.
Закрывают его клик вне меню, выбор действия, `Escape`, прокрутка страницы, `resize` и уход
со страницы.

**Наведение на отключённый пункт снимает выделение** и закрывает подменю этого уровня;
отметки владельцев, раскрытых уровнем выше, остаются. Фокус встаёт на сам уровень, так что
клавиши продолжают работать.

## Когда закрывается

- клик левой кнопкой вне дерева меню, включая сам привязанный контейнер;
- правый клик вне дерева меню и вне привязанного контейнера;
- клик по доступному пункту меню;
- `Escape` вне меню;
- прокрутка страницы;
- изменение размеров окна;
- уход вкладки в фон;
- уход фокуса из окна;
- уход курсора за пределы `autoHideDistance`, если опция задана.

**Скроллом считается сдвиг, а не событие.** Позиция сверяется с той, что была на показе,
и совпадение означает, что не прокрутилось ничего. Прокрутка элемента сверке не
подлежит: своя позиция у элемента своя. Поэтому прокрутка панели, сделанная кодом в том же
такте, что и показ (`scrollIntoView`, виртуализация), закрывает меню так же, как
пользовательская.

Прокрутка внутри длинного списка меню его не закрывает — и список чужого экземпляра на той
же странице тоже. Внутренним считается любой скролл, цель которого лежит в дереве какого
угодно меню.

Глобальные слушатели закрытия заводятся в `attach`, поэтому список выше работает, пока
экземпляр привязан. Открытый через `open()` без привязки экземпляр закрывается `close()`,
`Escape` и `Tab`, а также кликом по доступному пункту. Показ с `dismissible` поднимает
глобальные правила и без привязки — на время показа.

## Длинные списки

У длинного списка нет полосы прокрутки: его листают колесом над самим списком, пальцем и
клавишами, а с мыши — наведением на зону у края рамки. Зон две, высота каждой задана токеном
`--vc-scroll-zone-height`.

Показываются зоны у того уровня, чей список не помещается, и у самого края гаснут, а не
исчезают. Зоны не входят в кольцо клавиатурной навигации и скрыты от чтения с экрана.

Пока курсор держит зону, выделение с пункта снимается. Колесо над зоной не делает ничего:
ни страница не прокручивается, ни меню не закрывается. Колесо над самим списком
прокручивает список, как обычно.

Уход курсора с дерева меню снимает выделение с последнего открытого уровня и только один
раз; отметки владельцев раскрытых подменю остаются.

## Открытие без привязки

`attach` не подписывается ни на `keydown`, ни на `keyup`, и на привязанном контейнере
`Enter`, `Space` и `F10` не открывают ничего. Chromium при этом сам синтезирует
`contextmenu` по `ContextMenu` и `Shift+F10`, то есть на нём меню всё-таки открывается с
клавиатуры; Firefox и WebKit такого не делают, и ни один из трёх не синтезирует
`contextmenu` по `Enter`, `Space` и `F10`.

На документ `attach` вешает свой `keydown` в capture-фазе, но он ловит **только** `Escape` и
закрывает уже открытое меню, а не открывает его. Если меню должно открываться с клавиатуры,
добавьте триггер сами: обычно это кнопка или `role`-элемент с обработчиком, зовущим
`open({ x, y })` по координатам кнопки.

## CSS-переменные

Переопределяются на `.vc-menu` или на любом его предке.

### Геометрия

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `--vc-padding` | `8px` | минимальный отступ уровня от края вьюпорта |
| `--vc-scale` | `1` | множитель всех длин меню; задаётся опцией [`scale`](#scale) |
| `--vc-item-height` | `28px` | высота пункта |
| `--vc-scroll-zone-height` | `16px` | высота зоны прокрутки у края длинного списка |
| `--vc-icon-size` | `16px` | сторона слота иконки |
| `--vc-chevron-size` | `12px` | колонка шеврона |
| `--vc-radius` | `8px` | скругление меню и пунктов |
| `--vc-animation-duration` | `140ms` | вход, выход и задержка отложенного закрытия |

`--vc-padding` обязан совпадать с константой `SAFETY_PADDING` из `src/constants.js`:
движок позиционирования считает отступ до края вьюпорта равным этому токену, и расхождение
сдвигает решение о том, в какую сторону развернуть меню у края. Остальные токены — базовые
величины: они не умножаются на `--vc-scale` сами, множитель подставляется в местах
использования.

`options.animationDuration` переопределяет `--vc-animation-duration` инлайном на каждом
уровне, и инлайн перебивает любую вашу таблицу стилей. `--vc-scale` в ряд не входит: его
значение задаёт автор.

### Типографика

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `--vc-font` | системный стек | гарнитура меню |
| `--vc-font-size` | `13px` | кегль |

### Палитра

| Переменная | По умолчанию (светлая) | Смысл |
| --- | --- | --- |
| `--vc-bg-solid` | `#ffffff` | непрозрачная подложка, подставляется там, где нет `backdrop-filter` |
| `--vc-bg` | `color-mix(in srgb, var(--vc-bg-solid) 72%, transparent)` | фон уровня |
| `--vc-text` | `#1f2023` | текст пункта, в том числе на активном |
| `--vc-muted` | `#6b7280` | шеврон и отключённый пункт |
| `--vc-hover-bg` | `color-mix(in srgb, var(--vc-text) 6%, transparent)` | подсветка пункта под курсором |
| `--vc-active-bg` | `var(--vc-hover-bg)` | заливка активного пункта, отдельная ручка настройки |
| `--vc-separator` | `color-mix(in srgb, var(--vc-text) 12%, transparent)` | рамка уровня и разделитель |
| `--vc-shadow` | `0 8px 28px rgba(15, 18, 25, 0.18)` | тень |

Заливка активного пункта по умолчанию равна мышиной: выделение с клавиатуры и с мыши не
должно выглядеть по-разному, а кольца фокуса нет нигде, так что заливка — единственный
признак выделения. Отступление от неё — осознанный отказ от гарантии контраста 4.5:1.

## Темы и `prefers-reduced-motion`

Тема задаётся опцией `theme` и попадает в атрибут `data-vc-theme` на каждом уровне. Логика
выбора палитры целиком в CSS, а модуль только ставит атрибут, поэтому любой токен
переопределяется вашей таблицей стилей без пересоздания меню. Сменить `theme` на живом
экземпляре нельзя.

Тёмная палитра: `--vc-bg-solid` `#1b1d21`, `--vc-text` `#e8eaed`, `--vc-muted` `#9aa1ab`,
`--vc-bg` — 76% подложки против 72% в светлой, `--vc-hover-bg` — 10% текста,
`--vc-separator` — 16% текста, `--vc-shadow` — `0 8px 28px rgba(0, 0, 0, 0.55)`.

Медиазапрос темы ограничен `[data-vc-theme="auto"]`.

`prefers-reduced-motion: reduce` отключает движение полностью, а не укорачивает его:

- выключаются переходы как класс свойств — на меню и на всех потомках, поэтому шеврон и
  подсветка не двигаются тоже. Работает именно выключение переходов, а не нулевая
  длительность: инлайновое значение уровня перебило бы медиазапрос;
- `transform` у самого меню снимается. Поворот шеврона на 180° при развороте подменю влево
  переживает `reduce`;
- отложенный `hidePopover()` не ставится вовсе — под `reduce` в CSS стоит `transition:
  none`, и отложенное закрыление погасило бы уровень мгновенно;
- отметка закрытия `data-vc-closing` при этом ставится: она снимает события с закрытого
  уровня.

Меню под `reduce` видно сразу после открытия, без ожидания кадра.

## Ограничения иконок

Иконка типа `svg` — это **недоверенная разметка**: она приходит от автора пункта и
подставляется в DOM как есть, поэтому очищается по белым спискам элементов и атрибутов, а
не по набору запретов. Всё, чего в списках нет, удаляется: элемент вместе с поддеревом,
атрибут у каждого уцелевшего элемента. Из прочих узлов остаются только текст и CDATA.
Корневому `svg` принудительно выставляются `width="100%"`, `height="100%"`,
`aria-hidden="true"`, `focusable="false"`, `overflow="hidden"` и канонический `xmlns`.

- **Иконку нужно инлайнить.** Разметка `type: 'svg'` — это строка в вашем коде, а не
  адрес. Внешний спрайт-лист через `use` не работает: ссылки `href` и `xlink:href`
  допускаются только фрагментные. Внешний спрайт с того же origin тоже вырежется.
- **Презентация задаётся presentation-атрибутами и CSS библиотеки.** Атрибут `style`
  вырезается целиком. Пишите `fill="currentColor"`, `stroke-width="1.5"` прямо в разметке,
  а мелкие правки делайте селектором `.vc-icon-slot > *`.
- **CSS-escape-последовательности вида `\75 rl(...)` санитизация не ловит.** Это
  осознанный остаток. Если иконки приходят из недоверенного источника — задайте CSP
  владельца страницы и держите иконки на своём origin. Санитизация уменьшает поверхность
  атаки, но не заменяет CSP.
- **Легаси-псевдонимы SVG 1.1 в camelCase вырезаются:** `strokeWidth`, `fillOpacity`,
  `clipRule`, `stopColor`, `textAnchor`, `fontSize`, `fontFamily`, `letterSpacing`.
  **Симптом молчаливый:** ничего не падает, иконка просто выглядит не так. Проверяйте такие
  файлы глазами.
- **Атрибут `id` внутри иконки сохраняется** — без него `use` и градиенты не ссылались бы
  сами на себя. После вставки `use href="#id"` ищет элемент во всём документе. Свои `id`
  делайте уникальными на всю страницу, и **не используйте префикс `vc-`** — он занят
  библиотекой.
- **Иконка, чей `viewBox` обрезает содержимое намеренно, будет обрезана:** корню
  принудительно ставится `overflow="hidden"`, а авторский `overflow` перебил бы правило
  UA-стилей. Если содержимое должно выходить за `viewBox` — отдайте это отдельным
  элементом рядом.
- **`display` и `visibility` не принуждаются**, и потому `display="none"` отрисует иконку
  в никуда — молча. Уберите атрибут, если он не нужен.
- **`filter`, `marker-*`, `pattern*`, `color-interpolation-filters` и текстовые атрибуты
  разрешены, хотя соответствующие элементы в белый список не входят.** Позиция защитная.
  Но **читать белый список атрибутов как обещание отрисовки нельзя**: `filter`, `marker`,
  `pattern`, `text` и `tspan` в белый список элементов не входят и вырезаются вместе с
  поддеревом, так что разрешённый `filter="url(#f)"` ссылается в ничто.

### Иконки `emoji` и `raster`

`{ type: 'emoji', value: '📄' }` — символ в `span.vc-icon`, помеченный `aria-hidden`, чтобы не
дублировать озвучку лейбла.

`{ type: 'raster', value, alt }` — `img` с обязательным непустым `alt`. Принимаются только
`http:`, `https:` и `data:image/…`; остальные схемы отбрасываются, и элемент остаётся без
`src`.

Описание иконки предъявляет `iconAction` и проверяется на показе: `open()` бросает
`TypeError` с путём вида `vc-3-0:2.iconAction.alt`, если `alt` пуст, `value` пуст, тип не
из трёх или само описание не объект.

## Демо

```bash
npm run serve
```

Демо отдаётся на `http://127.0.0.1:4173/` (порт меняется переменной `PORT`). Страница
показывает двенадцать сценариев: базовое меню, вложенность, отключённые пункты, иконки
всех трёх видов, длинный список, масштаб меню, автоскрытие, удержание кнопки, удержание
левой кнопки, показ из чужого кода, всё вместе и события фокуса. Правый клик по любому
блоку сценария открывает его меню; переключатель в шапке меняет тему страницы.

Блок «Масштаб меню» — единственный, у кого задан `scale`, и он же единственный, чьё меню
пересобирается на ходу: ползунок в блоке меняет множитель и строит экземпляр заново.

Блок «События фокуса» ведёт на каждом пункте журнал `focusAction` и `blurAction` — видно,
что стрелка пишет то же, что и курсор, и что у пункта-владельца после `ArrowRight`
выделение остаётся, а `blur` всё равно приходит: фокус ушёл в подменю.

Отдельный стенд показа из чужого обработчика — `http://127.0.0.1:4173/Demo/edge/`.
Левая кнопка показывает меню вызовом из своего обработчика, правая — тем же вызовом с
`dismissible`.
