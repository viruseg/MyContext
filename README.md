# MyContext

Контекстные меню для браузера на чистом ES-модуле. Без рантайм-зависимостей, без
сборки, с Top Layer, неограниченной вложенностью подменю и полной клавиатурной
навигацией по открытому меню.

## Назначение

MyContext показывает меню по правому клику в точке, где стоит курсор, и держит его
внутри вьюпорта: корневой уровень появляется рядом с курсором, каждый уровень
подменю — рядом со своим пунктом-владельцем и разворачивается влево, когда справа
не хватает места. Вложенность не ограничена, список длинного уровня прокручивается
внутри рамки, а само меню живёт в Top Layer, поэтому не перекрывается ни заголовком,
ни модальным диалогом, ни `z-index` страницы.

- **Ноль зависимостей.** В `package.json` нет поля `dependencies`; в рантайме нет ни
  одного импорта, кроме вашего кода.
- **Ноль сборки.** Модуль — обычный ES-модуль из репозитория, браузер читает его как
  есть. `index.js` экспортирует ровно один символ — класс `MyContext`.
- **Меню в Top Layer.** Каждый уровень — свой элемент с `popover="manual"`, и все
  они лежат соседними узлами в `<body>`, а не внутри пункта: `backdrop-filter` и
  анимация масштаба на родителе создают containing block и ломают позиционирование
  относительно вьюпорта.
- **Клавиатура.** После открытия меню целиком проходится с клавиатуры, без единого
  движения мыши.
- **Зоны прокрутки.** Длинный список листают две зоны у краёв рамки, а системной
  полосы у списка нет: кроме своей толщины, сужавшей колонку подписей, у неё не было
  ничего. Зоны не входят в кольцо клавиатурной навигации и скрыты от чтения с
  экрана, а у упора гаснут, а не исчезают, — иначе список уехал бы из-под курсора
  ровно тогда, когда зона перестала его вести.
- **Темы.** `auto` следует за системной схемой, `light` и `dark` задают её явно.
  Вся палитра — в CSS-переменных.
- **Автоскрытие по желанию.** `autoHideDistance` прячет меню, когда курсор отошёл
  дальше заданного расстояния от всех показанных уровней, и по умолчанию выключено:
  меню, которое не прячется само, — правило, а не исключение.
- **Решение до показа.** `isArmableAction` позволяет пропустить нажатие мимо меню и
  узнать цель нажатия раньше, чем построен корень: подписи и доступность пунктов
  читаются при показе, и без предиката они отвечали бы на предыдущий.
- **Закрытие всего разом.** `MyContext.closeAll()` закрывает меню всех живых
  экземпляров на странице — для приложения, у которого нет ссылок на экземпляры:
  смена маршрута, открытое модальное окно, `Escape` на документе.

## Требования

Жёсткое требование одно — **Popover API и Top Layer**, то есть
`HTMLElement.prototype.showPopover`. Без него `attach()` бросает `Error` с
названием требования, а меню показать нечем: всё построено на `showPopover()` и
`hidePopover()`. Базовая линия движков: Chrome и Edge 114, Firefox 125, Safari 17.

Появление и исчезновение уровней анимируются через `@starting-style` и
`transition-behavior: allow-discrete`; это дополнительное требование, и там, где оно
не поддержано, меню остаётся рабочим, но переходов не будет.

`prefers-reduced-motion: reduce` обрабатывается и в CSS, и в JS: длительность
обнуляется, а отложенный `hidePopover()` не ставится вовсе (см. «Поддержка тем и
`prefers-reduced-motion`»).

## Установка

```bash
npm install
```

Зависимости устанавливаются только для разработки: Playwright, TypeScript и типы
Node. В рантайме библиотека не нуждается ни в чём.

Подключение состоит из двух файлов — таблицы стилей и модуля:

```html
<link rel="stylesheet" href="./styles/mycontext.css" />
<script type="module">
  import { MyContext } from './src/index.js';
</script>
```

В `package.json` нет ни поля `dependencies`, ни полей `main` и `exports`, и пакет
помечен `private`: библиотека не публикуется и не проходит через сборщик. Её
подключают файлами — скопировать `src/` и `styles/` к себе либо отдавать
статикой оттуда, где они лежат.

Модуль обязательно должен отдаваться по `http(s)`, а не с `file://`: браузер
запрещает загрузку ES-модулей с файловой системы. Штатный способ — любой
статический сервер; в репозитории для этого есть `npm run serve`, он же поднимает
демо (см. «Демо»).

Подключать таблицу стилей обязательно: в ней лежат и геометрия (сетка пункта,
`max-width`/`max-height` уровня), и палитра, и анимации. Без неё меню откроется, но
не будет выглядеть меню.

## Использование

```js
import { MyContext } from './src/index.js';

const menu = new MyContext(
  [
    {
      labelAction: () => 'Открыть',
      iconAction: () => ({ type: 'emoji', value: '📂' }),
      action: () => console.log('открыть'),
      submenuAction: () => [
        { labelAction: () => 'Недавние', action: () => console.log('недавние') },
        {
          labelAction: () => 'Проект',
          iconAction: () => ({
            type: 'svg',
            value: '<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 16 16">'
              + '<path d="M2 2h12v12H2z" fill="currentColor"/></svg>',
          }),
          submenuAction: () => [
            { labelAction: () => 'Черновик', action: () => console.log('черновик') },
            { labelAction: () => 'Готово', action: () => console.log('готово') },
          ],
        },
      ],
    },
    { type: 'separator' },
    {
      labelAction: () => 'Вставить картинку',
      iconAction: () => ({ type: 'raster', value: '/icons/picture.png', alt: 'Картинка' }),
      action: () => console.log('вставить'),
    },
    {
      labelAction: () => 'Склеить два файла',
      iconAction: () => ({ type: 'emoji', value: '🧩' }),
      // Предикат зовётся при каждом показе меню, и ответ не из `true` отключает
      // пункт: он не входит в цикл клавиатурной навигации, мышью по нему не
      // попасть, а его действие не зовётся. Непустое подменю у отключённого
      // пункта не делает его владельцем: шеврона, `aria-haspopup` и `aria-owns` у
      // него не будет, и раскрывать всё равно нечего.
      isEnabledAction: () => false,
      submenuAction: () => [{ labelAction: () => 'Что угодно' }],
    },
  ],
  { label: 'Меню файла', theme: 'auto' },
);

menu.attach(document.querySelector('#workspace'));
```

`attach` подписывается ровно на одно событие — `contextmenu` на переданном
контейнере, и подавляет системное меню внутри него. **Открывается меню правым
кликом по контейнеру.** Единственный программный путь — `open({ x, y })`, и он же
нужен для сценариев вроде «меню по кнопке»:

```js
document.querySelector('#paste').addEventListener('click', (event) => {
  menu.open({ x: event.clientX, y: event.clientY });
});
```

**Клавиатурного способа открыть меню через API нет.** `attach` не подписывается ни
на `keydown`, ни на `keyup`, и на привязанном контейнере `Enter`, `Space` и `F10`
не открывают ничего — это можно проверить на любом из трёх движков. Chromium при
этом сам синтезирует `contextmenu` по клавише `ContextMenu` и по `Shift+F10`, то
есть на нём меню всё-таки открывается с клавиатуры; Firefox и WebKit такого не
делают, и ни один из трёх не синтезирует `contextmenu` по `Enter`, `Space` и `F10`.
На документ `attach` вешает свой `keydown` в capture-фазе, но он ловит **только**
`Escape` и закрывает уже открытое меню, а не открывает его. Если меню должно
открываться с клавиатуры, добавьте триггер сами: обычно это кнопка или
`role`-элемент с обработчиком, зовущим `open({ x, y })` по координатам кнопки.

Внутри уже открытого меню клавиатура работает полностью:

| Клавиша | Действие |
| --- | --- |
| `ArrowDown` / `ArrowUp` | следующий / предыдущий доступный пункт, по кругу |
| `Home` / `End` | первый / последний доступный пункт |
| `ArrowRight` | открыть подменю пункта-владельца и перейти в него |
| `ArrowLeft` | закрыть текущий уровень и вернуться на пункт-владелец |
| `Enter` / `Space` | вызвать действие пункта и закрыть меню; у пункта-владельца — открыть подменю; без выделенного пункта ничего не делает |
| `Escape` | закрыть текущий уровень; на корневом — всё меню |
| `Tab` | закрыть меню и вернуть фокус контейнеру |

Клавиша достаётся не тому уровню, где стоит фокус, а **текущему** — самому глубокому
из открытых, то есть открытому последним. Это различает два состояния, которые иначе
неразличимы: подменю, открытое мышью, оставляет фокус на владельце в родительском
уровне, и без этого правила стрелка поехала бы по строке под курсором вместо того,
что пользователь видит. Перемещение (`ArrowDown`, `ArrowUp`, `Home`, `End`) и уход
(`ArrowLeft`, `Escape`) достаются текущему уровню — в частности, `Escape` при открытом
подменю закрывает подменю, а не всё меню. Раскрытие и активация (`ArrowRight`,
`Enter`, `Space`) остаются на уровне, из которого пришла клавиша: они отвечают на
вопрос «что выделено», а выделение принадлежит уровню, где стоит фокус, — и
`ArrowRight` на владельце открытого подменю входит в него, а не пустую строку.
`Tab` уровней не знает: он всегда закрывает всё меню.

Разделители и отключённые пункты в цикл навигации не входят и подсветки не получают.
Клик по пункту-владельцу открывает его подменю, а собственное действие владельца не
зовёт — ни мышью, ни с клавиатуры. Выделения сразу после открытия нет, а признак
выделения один: заливка активного пункта, кольца фокуса нет ни на пункте, ни на
уровне.

**Наведение на отключённый пункт снимает выделение и закрывает подменю этого
уровня.** Подсветка не должна висеть на последнем доступном пункте, пока курсор
стоит на серой строке: меню в таком виде выглядит заблокированным на том, чего
пользователь не выбирал. Отметки владельцев подменю, раскрытых уровнем выше,
остаются — они показывают путь раскрытия, а не выбор; закрывается подменю,
открытое с уровня, на котором стоит курсор. Фокус при этом встаёт на сам уровень,
так что клавиши продолжают работать и `ArrowDown` встаёт на первый доступный пункт.
Разделитель сюда не относится: он высотой в пиксель, и курсор пересекает его на
каждом проходе мимо, то есть выделение мигало бы постоянно.

Меню само закрывается при клике левой кнопкой вне дерева меню — включая сам
привязанный контейнер, — при правом клике вне дерева меню и вне привязанного
контейнера, при клике по доступному пункту меню, при `Escape` вне меню, при прокрутке
страницы, при изменении размеров окна, при уходе вкладки в фон, при уходе фокуса из
окна и — если задана опция `autoHideDistance` — при уходе курсора за её пределы
(см. [`autoHideDistance`](#autohidedistance)). Прокрутка внутри длинного списка меню его
не закрывает — и список чужого экземпляра на той же странице тоже, хотя два
экземпляра на странице обычны. Внутренним для прокрутки считается любой скролл,
цель которого лежит в дереве какого угодно меню, а не только этого: закрытие
вызывается уездом страницы из-под привязанного контейнера, а список под ним не уезжает
и его геометрию не меняет, так что листание чужого меню не должно сносить соседнее.

У длинного списка нет полосы прокрутки: его листают колесом над самим списком,
пальцем и клавишами, а с мыши — наведением на зону у края рамки: зон две, и высота
каждой задана токеном `--vc-scroll-zone-height`. Показываются зоны у того уровня, чей
список не помещается, и у самого края гаснут, а не исчезают: исчезновение сдвинуло бы
список из-под курсора ровно тогда, когда он перестал им двигаться.

Пока курсор держит зону, выделение с пункта снимается: подсветкой горел бы тот, кого
никто не выбирал. Снимается оно у того уровня, чья зона под курсором, — отметки
владельцев раскрытых подменю над ним остаются. Колесо над зоной не делает ничего: ни
страница не прокручивается, ни меню не закрывается — зона листается наведением, а
колесо над ней погашено. Колесо над самим списком прокручивает список, как обычно.

Уход курсора с дерева меню снимает выделение с последнего открытого уровня и только
один раз: пока курсор снаружи, двигаться ему уже незачем, и сбрасывать на каждом
движении значило бы стирать то, что поставила клавиатура. Отметки владельцев
раскрытых подменю остаются: они означают «подменю раскрыто», а не «курсор стоит на
этом пункте», и по ним видно путь. Фокус с этого уровня, если он там стоял, встаёт на
элемент уровня — меню продолжает отвечать на клавиши с той же глубины.

Состоянием подменю владеет активный пункт родительского уровня, а не положение
курсора, — так же, как в системных меню. Пока активен пункт `A`, его подменю открыто;
переход на соседний пункт того же уровня закрывает его: у соседа с подменю открывается
подменю соседа, у соседа без подменю остаётся активным только сосед. Возврат курсора
на владельца уже открытого подменю не меняет ничего — ни показа, ни закрытия: активный
пункт прежний, значит прежнее и подменю. Уход курсора в
нейтральную область — зону прокрутки, поля меню, разделитель, пустоту страницы —
подменю не закрывает ничем: отслеживать координаты курсора не нужно, и обработчики
ухода курсора на контейнер подменю не навешиваются. Снимают его клик вне меню, выбор
действия, `Escape`, прокрутка страницы, `resize` и уход со страницы. Открытое в
нативном стиле меню не следует за курсором. Отключённый пункт в этот список не
входит: на него наводят так же, как на любую строку, и подменю его уровня он
закрывает.

Опция `autoHideDistance` — единственное исключение из этого правила, и она включается
сама по себе. Меню, у которого она задана, прячется, когда курсор отошёл дальше порога
от всех показанных уровней сразу; расстояние считается от края прямоугольника, а
открытое подменю продлевает зону, поэтому уход в сторону подменю закрывает не его.
Подробности, включая то, почему порогом не может быть ноль и почему у правила нет
предыстории, — в [`autoHideDistance`](#autohidedistance).

**Скроллом считается сдвиг, а не событие.** Правило «прокрутка закрывает меню» не
закрывает меню событием `scroll`, пришедшим без сдвига страницы. Позиция страницы
сверяется с той, что была на показе, и совпадение означает, что не прокрутилось ничего,
а закрывать нечем: меню у нижнего края экрана убрало бы само себя.
Прокрутка элемента сверке не подлежит: своя позиция у элемента своя, и отличить
чужой пересчёт от сдвига нечем. Поэтому прокрутка панели, сделанная кодом в том же
такте, что и показ — виртуализация списка, `scrollIntoView`, — закрывает меню так же,
как пользовательская.

Опция `pressAndHold` меняет сам этот список: под ней меню открывается нажатием
кнопки и живёт до её отпускания, а не до клика, `Escape` или прокрутки. Разбор
отпускания — над доступным пунктом действие и закрытие, над всем остальным молчаливое
закрытие; нажатие второй кнопкой закрывает откуда угодно. Подробности, включая
почему правый клик перестаёт открывать меню, — в
[`pressAndHold`](#pressandhold).

Глобальные слушатели закрытия заводятся в `attach`, поэтому список выше работает,
пока экземпляр привязан — `autoHideDistance` из списка не исключение. Открытый через
`open()` без привязки (и после `detach()`)
экземпляр закрывается `close()`, `Escape` и `Tab` внутри меню, а также кликом по
доступному пункту. Показ с [`dismissible`](#optionsdismissible) поднимает глобальные
правила и без привязки — на время показа, а не навсегда.

### Пункты и подменю

Пункт — объект, у которого подпись, иконка и подменю заданы действиями, а не
значениями: они нужны на показе, и раньше показа их не существует. Пункт — объект
с полями:

| Поле | Тип | Обязательность |
| --- | --- | --- |
| `labelAction` | `() => string` | обязательно; вернул не строку или пустую — `TypeError` |
| `id` | `string` | необязательно, копируется в `data-id` и в ключ пункта не входит |
| `iconAction` | `() => IconConfig` | необязательно; вернул не описание иконки — `TypeError`. Без него слот остаётся пустым, но занимает место |
| `action` | `(event) => void` | необязательно; вызывается по клику и по `Enter`/`Space`, кроме пункта-владельца непустым подменю |
| `isEnabledAction` | `() => boolean` | необязательно; зовётся при каждом показе меню, ответ не из `true` отключает пункт |
| `submenuAction` | `() => MenuItem[]` | необязательно; вернул не массив или пустой — `TypeError`. Непустой массив и доступность по `isEnabledAction` делают пункт владельцем |
| `handoffAction` | `(event: Event) => void` | необязательно; не функция — `TypeError`. Вместе с доступностью по `isEnabledAction` делает пункт отдающим управление; см. ниже |
| `version` | `number` | необязательно, `0` по умолчанию; см. «Состав уровня» ниже |

Разделитель — это `{ type: 'separator' }`. Имя `type` обязано быть ровно
`'separator'`: конструктор бросает `TypeError` на любое другое значение, так что
опечатка автора не превратится молча в пункт. Лишние поля у разделителя не
отклоняются и просто игнорируются.
Пустой корневой массив отклоняется конструктором: меню без пунктов не рисуется.
Пустое подменю — ошибка, а не «не подменю»: подменю, нечем раскрывать, не
существует, и сказать об этом автору лучше на показе, чем молча
показать пункт без шеврона.

Ушедшие из контракта поля `label`, `icon`, `submenu` и `disabled` больше не
принимаются: конструктор бросает на каждом из них `TypeError` с путём до поля и
подсказкой. Отклоняются, а не игнорируются, — иначе оставленное автором
`label: 'Открыть'` молча убрало бы подпись, а `disabled: true` сделало бы пункт
активным, и ошибка каждой из них вылезла бы там, где её не ждут.

Пять действий зовутся **на каждом показе**, а не один раз при создании
экземпляра. Подпись и иконка следуют за тем, что изменилось, а состав подменю
отвечает на новое состояние:

```js
{
  // Показ открывает новый документ — подпись узнаёт об этом сама.
  labelAction: () => (document.hidden ? 'Показать' : 'Скрыть'),
  // Непустое подменю и доступность делают пункт владельцем; у отключённого
  // пункта шеврона, `aria-haspopup` и `aria-owns` не будет, и раскрывать всё
  // равно нечего.
  isEnabledAction: () => clipboard.length > 1,
  submenuAction: () => [
    { labelAction: () => 'В один' },
    { labelAction: () => 'В новый' },
  ],
}
```

Ошибки проверяются в момент показа, а не в конструкторе: до показа значений нет.
`labelAction` обязан вернуть непустую строку, `iconAction` — описание иконки по
«Ограничениям иконок», `submenuAction` — непустой массив пунктов. Нарушение
бросает `TypeError` из `open()` с путём до поля вида `vc-3-0:2.labelAction`.
Исключение самого автора — из любого из действий — не гасится и уходит из
`open()` вызывающему, как и исключение из `action`.

`action` получает настоящее событие активации — мышиный клик или клавиатурную
активацию — с настоящей целью. Исключение из обработчика не проглатывается: его
получает вызывающий, а меню закрывается в `finally` — за одним исключением: если
действие само вызвало `open()`, закрытие пропускается, иначе открытое им заново меню
убило бы тот же клик.

`isEnabledAction` — единственный источник доступности пункта: прежнее поле
`disabled` заменено им целиком. Предикат получает аргументов и возвращает
`boolean`; без поля пункт доступен. Сравнение строгое, `=== true`: не-булево — это
не «достаточно истинно», а предикат, не ответивший на заданный вопрос, и забытый
`return` гасит пункт.

#### Отдача управления: `handoffAction`

Владелец подменю раскрывает уровень, нарисованный этим же меню. `handoffAction`
передаёт управление **наружу**: что и где показать, решает автор, а меню обязано
только уйти с экрана.

```js
const radial = new Pielet({ /* … */ });

const menu = new MyContext([
  {
    labelAction: () => 'Цвет',
    handoffAction: (event) => {
      radial.open(event.clientX, event.clientY);
    },
  },
]);
```

Правила:

- **Срабатывает по всем путям активации**: наведение с задержкой как у владельца
  подменю, нажатие — без неё, клик, `Enter` и `Space`. На удержании отдачу несёт
  наведение: нажатие по пункту во время удержания перехватывает разбор документа и
  закрывает меню — так устроено правило «вторая пресса закрывает жест».
- **Меню уходит безусловно, и в `finally`.** То, что автор покажет вместо него,
  ему не принадлежит, и перекрывать его не должно; исключение автора не должно
  оставлять наш уровень висеть поверх того, что он открыть не сумел. Как и у
  `action`, если действие само вызвало `open()`, закрытие пропускается.
- **Действие зовётся один раз на показ.** Наведение планирует показ, нажатие
  показывает его немедленно, а `click` приходит следом — три события на одну
  активацию, и три вызова автор бы не хотел.
- **Владельцем подменю пункт не становится.** У него нет подменю, и раскрывать
  нечего: шеврон и `aria-haspopup` ему полагаются, а `aria-owns` — нет, вести его
  некуда.
- **Отключённый пункт не отдаёт.** Правило то же, что у `action`: негодный пункт
  не отвечает ни за что.

Событие активации достаётся как есть: по наведению это `pointerenter`, по нажатию
`pointerdown`, с клавиатуры `keydown`. Что с координатами делать — решает автор, и на
клавиатуре координат у события нет вовсе.

Поле проверяется по форме, а не по смыслу: не-функция бросает `TypeError` с путём до
поля. Значение `handoffAction` не проверяется — это поле зовёт оркестратор, показ, а
не конструктор, и до показа пункта о нём нечего знать.

### Состав уровня

Состав уровня задаётся значениями, а не ссылками на объекты: автор вправе отдать
на каждом показе новый массив новых пунктов, и различие ссылок само по себе ни о
чём не говорит. Перед каждым показом состав сверяется по **отпечатку** — по
длине, порядку, разделителям, значениям `id` и `version`:

- **отпечаток совпал** — уровень не перестраивается, обновляются только ответы
  действий его пунктов (подпись, иконка, владелец подменю, доступность);
- **отпечаток разошёлся** — уровень перестраивается целиком вместе со всем, что
  открыто из него, и строится заново под тем же `id`, потому что `aria-owns`
  пункта-владельца уже назван.

Совпадение отпечатка означает структурное тождество: перестраивать нечего. Но
запись пункта в карте действий перезаписывается всё равно — при структурно том же
составе, предъявленном новыми объектами, по клику зовётся действие именно нового
пункта.

Отпечаток не различает новые объекты, и это правильно: подпись, иконка и подменю
у них и так перечитываются на каждом показе. Но иногда этого мало — например, автор
заменил `submenuAction` на новую функцию, а структура состава не изменилась и
перестраивать нечего. Для таких случаев есть `version`: он входит в отпечаток, и
его подъём заставляет уровень перестроиться при неизменившейся структуре.

```js
{
  labelAction: () => 'Формат',
  // Подменю собирается из того, что в буфере обмена, и его форма меняется сама.
  submenuAction: () => clipboardFormats().map((format) => {
    return { labelAction: () => format.name, action: () => paste(format) };
  }),
  // Заменили выше `submenuAction` на новую функцию — поднимите `version`, и
  // уровень перестроится, хотя длина и порядок остались теми же.
  version: 2,
}
```

`version` — необязательное конечное число, `0` по умолчанию; не-число
отклоняется. Ответственность за его подъём лежит на авторе: библиотека не знает,
заменено ли действие, и опирается ровно на то, что автор сказал полем.

## Справочник API

### `new MyContext(items, options?)`

Создаёт меню. Форма конфигурации проверяется сразу, и экземпляр с негодной
конфигурацией не появляется: бросается `TypeError`, а в сообщении назван путь до
поля (`items[1].labelAction`). Слушателей на страницу конструктор не вешает.

Проверяется только корневой состав. Значения действий известны на показе, и до
показа их нет: подпись, иконку и состав подменю проверяет рендерер при сборке
уровня, и об ошибке сообщает `open()`, а не конструктор.

Поля `options`:

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `theme` | `'auto' \| 'light' \| 'dark'` | `'auto'` | оформление всех уровней |
| `animationDuration` | `number`, мс | `140` | вход, выход и задержка отложенного закрытия |
| `label` | `string` | `'Меню'` | доступное имя меню, ставится каждому уровню |
| `autoHideDistance` | `number`, px | `0` | на каком расстоянии от показанных уровней меню прячется само; `0` — никогда |
| `pressAndHold` | `'none' \| 'left' \| 'right' \| 'middle' \| 'any'` | `'none'` | какой кнопкой меню открывается и когда закрывается; `'none'` — показ по правому клику |
| `isArmableAction` | `(event: PointerEvent) => boolean` | — | разрешать ли нажатие вооружать жест; ответ не из `true` оставляет меню закрытым |
| `destroyOnClose` | `boolean` | `false` | разбирать ли экземпляр при закрытии; меню, заведённое на один показ |

Одна величина `animationDuration` управляет всеми тремя, иначе выход не совпадёт с
задержкой снятия.

Ополя проверяются так же, как пункты, и каждое значение вне перечисленного
отклоняется: неизвестная `theme` иначе попала бы в разметку дословно и тёмное
приложение тихо получило бы светлое меню, а `NaN` в `animationDuration` дал бы
недействительный токен и анимация пропала бы без единой ошибки. Пустой `label`
тоже отклоняется: имя уровня обязано быть читаемым, и подставлять его по умолчанию
значило бы молча записать `aria-label=""`. Значение `pressAndHold` проверяется по
списку: любое другое молча превратилось бы в «удержание не настроено», то есть в
прежнее поведение, и автор задал бы жест, а меню открывалось бы по правому клику.
`isArmableAction` проверяется по форме: нефункция молча превратилась бы в «спросить
некого», то есть в прежнее поведение, и автор задал бы запрет, а меню открывалось бы
всё равно. `destroyOnClose` проверяется по той же форме: молча проигнорированная опция
оставила бы экземпляр жить после закрытия, и подписки копились бы по одному разу на
каждый показ.

#### `autoHideDistance`

Расстояние считается от **края прямоугольника** до курсора, а внутри прямоугольника
оно нулевое. Меню прячется, когда курсор отошёл дальше порога **от всех**
показанных уровней сразу, — то есть проверяется расстояние до ближайшего из них:

```js
const menu = new MyContext(items, { autoHideDistance: 120 });
```

Открытое подменю продлевает зону: уход в сторону открытого подменю — это не уход из
меню, даже если до корня уже далеко. И наоборот, уход вниз от нижнего края длинного
подменю закрывает меню, хотя корневой уровень рядом. Зазор между уровнями пуст и
меряется от обеих рамок, поэтому курсор идёт по нему без риска закрыть меню, пока
не отойдёт за порог.

Что стоит знать:

- **Ноль — это «выключено», а не «закрывать в первом же пикселе за краем».** Порог
  меньше расстояния между уровнями (`SUBMENU_OFFSET`) или высоты пункта закрывал бы
  меню на пути к подменю и при движении между пунктами одного уровня.
- **Предыстории у правила нет.** «Был ли курсор в меню» не спрашивается, поэтому
  меню, открытое программно (`open()` по горячей клавише) в стороне от курсора,
  спрячется по первому же движению мыши. Если это не устраивает — оставьте опцию
  равной `0` и закрывайте сами.
- **Закрытие возвращает фокус** привязанному контейнеру, как `Escape` и `close()`:
  курсор своим уходом фокус никуда не уводит, и оставлять его на гаснущем уровне
  нельзя. Клик по странице, скролл и `resize` фокус не возвращают — там событие само
  уводит фокус.
- **Живёт на тех же глобальных слушателях, что и все прочие правила закрытия**, а те
  вешает `attach()` — либо сам показ с [`dismissible`](#optionsdismissible). У
  непривязанного экземпляра, показанного без `dismissible`, правило не работает.
- **Правило одинаково для мыши, пера и касания** — отдельно для `pointerType` его
  нет.

#### `pressAndHold`

Переводит меню с правого клика на удержание кнопки:

```js
const menu = new MyContext(items, { pressAndHold: 'left' });
```

Значение называет кнопку, а не включает жест: `'none'` — прежнее поведение,
`'left'`, `'right'`, `'middle'` — своя кнопка, `'any'` — любая из них.

Жизненный цикл целиком:

- **Нажатие показывает меню в точке нажатия.** Не в точке прихода `contextmenu` и не
  после паузы: показывается сразу же, как системное меню по удержанию.
- **Отпускание закрывает меню всегда.** Это и есть «кнопка отпущена — меню ушло»,
  никакого таймера и никакого ожидания.
- **Отпускание над доступным пунктом исполняет его действие.** Порядок один на все
  пути активации: сначала закрытие, потом действие, а не наоборот. Так действие
  видит меню уже закрытым, и открытое им заново меню не убивается закрытием, начатым
  по той же прессе. Пункт ищется до закрытия, потому что с `destroyOnClose` закрытие
  стирает карту действий. Исключение из действия не оставляет меню висеть.
- **Действие не должно звать меню обратно.** На этом пути, в отличие от клика,
  экземпляр к моменту действия уже может быть разобран — с `destroyOnClose` он
  разобран всегда. `open()` или `close()` изнутри `action` бросят `Error`.
- **Фокус после отпускания над пунктом возвращается на привязанный контейнер**, а
  после отпускания мимо пунктов — нет: выбор пункта возвращает фокус, как и клик по
  нему, а уход курсора в пустоту — не выбор.
- **Отпускание над всем остальным закрывает молча**: над отключённым пунктом,
  разделителем, полями каркаса, зоной прокрутки и пустотой страницы.
- **Отпускание над пунктом-владельцем подменю закрывает молча.** Подменю на
  отпускании не раскрывается и действие владельца не вызывается — так же, как по
  клику.
- **Нажатие любой другой кнопкой во время удержания закрывает меню** независимо от
  того, где пришлось: по странице или по самому меню. Кнопку второй раз без отпускания
  не нажать, зато другую — можно, и она гасит жест намертво.

Что стоит знать:

- **Правый клик перестаёт открывать меню.** При включённой опции `contextmenu`
  больше не показывает меню — это единственный способ открыть, иначе отпускание
  правой кнопкой исполнило бы действие, а следом вернуло бы пустое меню. Системное
  меню браузера при этом по-прежнему гасится на привязанном контейнере.
- **Наведение во время удержания работает как обычно**: пункты подсвечиваются,
  подменю раскрываются по наведению, вложенные подменю открываются так же. Именно
  поэтому до пункта подменю можно дойти, не отпуская кнопку.
- **Жест снимается любым закрытием, а не только отпусканием.** `Escape`, прокрутка
  страницы, `resize`, уход вкладки в фон, потеря фокуса окна и автоскрытие гасят его
  одинаково, и отпускание после этого уже ничего не делает.
- **С автоскрытией правила не конфликтуют.** Автоскрытие меряет расстояние до края
  ближайшего показанного уровня, а меню открывается под самым курсором, поэтому
  жест до пункта подменю автоскрытие не прерывает. Если автоскрытие всё же закрыло
  меню, удержание снимается вместе с ним, а следующее нажатие вооружает жест
  заново.
- **Нажатие гасит выделение текста и нативный перетаскивание.** Иначе протяжка
  курсора к пункту выделяла бы текст под ним. Фокусу вреда нет: в этом режиме
  нажатие по контейнеру всё равно открывает меню и уводит фокус в него.
- **Программный `open()` под опцией не меняется.** Меню, открытое кодом, живёт по
  прежнему циклу: закрывают его `Escape` и `close()`, а от остальных правил — ещё и
  `dismissible` (см. [`options.dismissible`](#optionsdismissible)). Новый цикл
  принадлежит жесту, а не экземпляру.
- **Работает только у привязанного экземпляра**, как и прежний показ: нажатие
  разбирает глобальный слушатель, а те вешает `attach()`.
- **Значение задаётся на всё время жизни меню и не переключается на показ:**
  добавить или убрать его можно только новым экземпляром.

#### `isArmableAction`

Предикат, решающий, вооружать ли нажатие жест удержания. Без него меню открывается
по любому нажатию нужной кнопки внутри привязанного контейнера:

```js
const menu = new MyContext(items, {
  pressAndHold: 'right',
  isArmableAction: (event) => event.target.closest('.photo') !== null,
});
```

Предикат зовётся на каждом нажатии подходящей кнопки и получает живой
`PointerEvent` этого нажатия. Ответ не из `true` оставляет меню закрытым, и жест не
вооружается: отпускание после такого отказа не исполнит действие пункта, которого
на экране нет.

Зачем он нужен. **Меню показывается по нажатию, а не по `contextmenu`.** Значит, к
моменту показа код автора доступна цель нажатия — и только она: подписи, иконки и
доступность пунктов читаются при показе, то есть уже после. Без предиката хост,
решающий по нажатию, узнаёт о цели слишком поздно, и подписи отвечают на предыдущий
показ. Предикат двигает это решение до показа:

```js
// Идентификатор жатого элемента становится известен до того, как построен корень.
let currentId = null;
const menu = new MyContext(items, {
  pressAndHold: 'right',
  isArmableAction: (event) => {
    const hit = event.target.closest('.photo');
    if (hit === null) return false;
    currentId = hit.dataset.id;
    return true;
  },
});
```

Что стоит знать:

- **Предикат зовётся последним из проверок нажатия.** Кнопка, привязанный контейнер
  и «не внутри самого меню» проверяются раньше: по нажатию мимо меню ответ одинаков,
  и лишний вызов только достал бы автора вопросом, на который у него нет ответа.
- **Сравнение строгое, `=== true`:** не-булево — предикат, не ответивший на заданный
  вопрос, и забытый `return` закрывает меню. Как у `isEnabledAction`.
- **Без предиката поведение прежнее**: меню открывается по любому нажатию нужной
  кнопки внутри привязанного контейнера.
- **Осмысленна только при `pressAndHold`, отличном от `'none'`.** При `'none'` жеста
  нажатия нет, опция не зовётся вовсе: автор задал бы запрет, а меню открывалось бы
  правым кликом.
- **Исключение из предиката не гасится** и уходит из обработчика нажатия, как
  исключение из любого другого действия автора. Меню при этом не показывается.
- **С несколькими меню на одном контейнере предикат и есть маршрутизация.** У
  `pressAndHold` нет выбора режима, какой есть у `contextmenu`: каждый привязанный
  экземпляр разбирает нажатие сам. Сколько меню покажет предикат, столько и
  откроется, поэтому у каждого он должен быть свой.

#### `destroyOnClose`

Меню, заведённое на один показ, само себя убирает:

```js
// Обработчик, который сам же показывает меню, и есть тот, кто его заводит.
element.addEventListener('contextmenu', (event) => {
  event.preventDefault();
  const menu = new MyContext(items, { destroyOnClose: true });
  menu.attach(element);
  menu.open({ x: event.clientX, y: event.clientY });
});
```

Зачем опция. Экземпляр, который автор создаёт на каждый показ, никто не разбирает:
ссылки на него нет ни у кого, кроме обработчика, а к следующему показу её там уже не
будет. Между показами он остаётся жив и держит на странице всё, из чего собран:
слушатель `contextmenu` на своём контейнере, глобальные правила закрытия, уровни в DOM
и запись в реестре живых. По одному разу на каждый показ, и на странице, где меню
показывают часто, это уже не «мелочь», а рост.

Что происходит при закрытии:

- **Разбирается всё сразу: подписки, задачи, карты, реестр.** Запись из реестра живых
  и слушатель `contextmenu` снимаются в том же такте, что и закрытие, то есть до
  того, как пользователь успеет снова ткнуть в контейнер.
- **Экземпляр объявляется уничтоженным сразу.** `open`, `attach`, `detach` и `close`
  бросают `Error` с тем же сообщением, что и после `destroy()`, а `destroy()` остаётся
  идемпотентным. Никакого «почти уничтоженного» состояния не появляется.
- **Контейнер перестаёт открывать меню.** Второй правый клик по нему откроет то, что
  покажет новый экземпляр. Мёртвый экземпляр на клик не отвечает вовсе, а не бросает
  из обработчика, поэтому ни меню, ни ошибки в консоли второй клик не даст.
- **Уровни снимаются в конце анимации выхода, а не сразу.** `destroy()` удалил бы их
  мгновенно, и меню, рассчитанное на один показ, пропадало бы ещё и без фейда. Под
  `prefers-reduced-motion: reduce` выхода нет, и разбор мгновенен.

Что стоит знать:

- **Разбор на любом закрытии**, а не только по выбору пункта: клик по пункту, `Escape`,
  клик вне, прокрутка, `resize`, уход вкладки в фон, потеря фокуса окна,
  [`autoHideDistance`](#autohidedistance), [`close()`](#close) и
  [`MyContext.closeAll()`](#mycontextcloseall). Закрытие у экземпляра одно, и опция
  работает на нём целиком.
- **Закрытие подменю закрытием меню не считается.** `Escape` на раскрытом подменю
  закрывает только его — так же, как без опции, — и следующий `Escape` закрывает
  корень и разбирает экземпляр. Разбор посреди показа убил бы меню, которым автор
  ещё ходит.
- **Переоткрытие на месте тоже не закрытие.** Повторный `open()` по уже открытому
  меню гасит уровни и показывает их в новой точке — это тот же показ, и экземпляр его
  переживает.
- **Одноразовый экземпляр нельзя воскресить.** Если закрытие уже произошло, тот же
  объект больше не покажет меню ни при каком вызове: следующий показ требует нового
  экземпляра. Если меню нужно открывать снова — не задавайте опцию и держите один
  экземпляр.
- **Ссылка на экземпляр после закрытия — мёртвая.** Из неё можно звать только
  `destroy()`, и то он ничего не делает. Не храните такой экземпляр в своём
  состоянии: он там не переживёт закрытие.
- **Работает вместе с `dismissible` и `pressAndHold`.** Обе опции отвечают за то, как
  меню открывается и чем закрывается, и обе переживают разбор: непривязанный
  одноразовый экземпляр, показанный с `dismissible: true`, после клика вне снимает с
  себя и глобальные правила.

### `attach(element)`

Подписывает контейнер на `contextmenu` и вешает глобальные слушатели закрытия.
Повторный вызов переносит привязку: предыдущий контейнер освобождается, иначе у
экземпляра было бы два контейнера. Возвращаемого значения нет.
Бросает `Error`, если экземпляр уничтожен или браузер не умеет Popover API.
Требование проверяется здесь, а не в конструкторе: без привязки экземпляр пригоден
для `open()` там, где автор и так работает со своим поповером, и падать рано было бы
невежливо.

### `detach()`

Снимает подписку с контейнера, ничего не разрушая: экземпляр остаётся пригодным
для `open()`. Вызов без привязки — не операция. Бросает `Error`, если экземпляр
уничтожен.

### `open({ x, y }, options?)`

Открывает корневой уровень в точке вызова, координаты вьюпорта, px. На закрытом меню
показ синхронный. На открытом — полный цикл: уровни гаснут на месте, в Top Layer, и
через `animationDuration` корневой показывается в новой точке; под
`prefers-reduced-motion: reduce` цикл проходит за один такт. Уровень и его пункты при
этом не пересоздаются, то есть повторный вызов не заводит второго меню. Фокус встаёт
на элемент уровня, а не на пункт: выделения после открытия нет, и первую же стрелку
разбирает меню, давая крайний доступный пункт — без фокуса на самом уровне открытое
меню было бы мёртвым для клавиатуры. Бросает `Error`, если экземпляр уничтожен.

Поле `options`:

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `armed` | `boolean` | `false` | показать меню внутри уже начатого жеста удержания; см. ниже |
| `dismissible` | `boolean` | `false` | поднять на время показа глобальные правила закрытия; см. ниже |

#### `options.armed`

```js
menu.open({ x: 200, y: 300 }, { armed: true });
```

Меню на удержании вооружается нажатием по своему привязанному контейнеру, и
отпускание кнопки его закрывает: жест разбирает событие, которым начался. `armed`
покрывает обратный случай — **кнопку держит вызывающий код, а меню он открывает уже
после нажатия**. Нажатия по контейнеру у такого меню не было, вооружения нет, и
разбирать отпускание некому: меню не закрылось бы ничем.

С `armed` поведение прежнее, только начало другое:

- **Кнопка, названная `options.pressAndHold`, считается уже зажатой.** Отпускание её
  закрывает меню, а если в этот момент под курсором доступный пункт — ещё и
  исполняет его действие. Порядок тот же, что у обычного удержания.
- **Жест вооружается по кнопке, а не по указателю.** Вооружение снаружи не знает,
  каким пальцем держит вызывающий код, и сверять его не с чем. Кнопка же названа в
  опции и у вызывающего перед глазами.
- **Привязка не требуется.** Подписка на отпускание поднимается самой опцией и
  снимается вместе с жестом — при закрытии, оттуда же снимается и всё прочее.
- **Остальное меню не меняется.** Подменю раскрываются по наведению, клавиатура
  работает, автоскрытие и `Escape` действуют как прежде.

Требует `pressAndHold`, отличного от `'none'`: при `'none'` кнопки нет, и закрывать
будет нечем — такая передача бросает `TypeError`. Не-логическое значение `armed`
бросает `TypeError` же: молчаливое «жест не вооружён» выдало бы опцию за сработавшую.

**Цикл выше живёт внутри одного экземпляра, и между экземплярами его нет.** Правый
клик по блоку другого экземпляра гасит чужое меню на месте и открывает своё в том же
такте: оба перехода идут одновременно, кросс-фейдом, по `animationDuration` каждый.
Экземпляры не знают друг о друге — каждый закрывает и открывает сам, — и ждать
выхода чужого меню некоему. Правая часть всегда принадлежит экземпляру блока, по
которому пришёл клик.

#### `options.dismissible`

```js
menu.open({ x: 200, y: 300 }, { dismissible: true });
```

Показ, за который отвечает чужой код. Пункт другого меню, кнопка на странице,
чужой обработчик — всё, что показывает меню не от нажатия по привязанному
контейнеру.

Зачем опция. Правила закрытия живут на глобальных слушателях, а их заводит
`attach()`. Показ от нажатия по контейнеру и правила закрытия приходят одним
методом, и меню, открытое из чужого обработчика, оказывается без обеих вещей:
привязывать ради него контейнер нечем, а показанное так меню не закрылось бы ничем.
`dismissible` разрывает эту связку и поднимает правила на время показа.

- **Правила те же, что у привязанного экземпляра, — целиком.** Клик вне меню, правый
  клик вне меню, прокрутка, `resize`, уход вкладки в фон, потеря фокуса окна — и
  [`autoHideDistance`](#autohidedistance), если он задан: его строка слушателя
  поднимается вместе с прочими. У непривязанного экземпляра, который раньше
  автоскрытия не знал, меню теперь спрячется по первому движению курсора — это тот
  же список, а не скидка на показ из чужого кода.
- **Подписка живёт до закрытия, а не до конца вызова.** Закрытие её снимает, поэтому
  экземпляр, который автор заводит на каждый показ, ими не течёт. У привязанного
  экземпляра опция ничего не меняет: правила уже подняты и держатся между показами,
  пока жив `attach()`.
- **Показ не изменился.** Никакого нового способа открыть меню опция не вводит:
  корневой уровень, фокус, подменю и клавиатура те же.
- **`detach()` во время такого показа правила снимает.** Меню останется на экране, но
  гасить его будет нечем, кроме `Escape` и `close()`. То же место у привязанного
  экземпляра: `detach()` снимает слушатели, а не только привязку.

Не-логическое значение `dismissible` бросает `TypeError`: молча не поднятые
правила выдали бы опцию за сработавшую, и меню осталось бы висеть.

**Все действия пункта перечитываются на каждом показе, а состав уровня
сверяется по отпечатку.** Предикат, ответивший не из `true`, снимает пункт с кольца
навигации, ставит ему `aria-disabled` и убирает признаки подменю, если они были;
подпись и иконка обновляются, а `submenuAction` отвечает заново. Это позволяет
выключить действие, изменить подпись или состав подменю, не заводя новый
экземпляр.

Изменение самого состава — числа пунктов, их порядка, разделителей, `id` или
`version` — приводит к полной перестройке уровня вместе со всем, что из него
открыто (см. «Состав уровня»). Повторный `open()` при этом не заводит второго
меню: новый уровень строится под тем же `id`.

### `openAsSubmenu(x, y)`

Показ как сабменю чужого меню, которое зовёт `open(x, y)`. Ради этого метода и
существует поле `menu` в пункте чужого меню: чужое зовёт `open` с двумя числами, а
наш принимает точку и опции.

Перевод мог бы лежать на авторе — обёртка
`menu: { open: (x, y) => ctx.open({ x, y }, { armed: true, dismissible: true }) }`
работает, — но тогда каждое чужое меню повторяет наше знание о том, какая именно
пара опций делает жест работоспособным. Здесь это знание одно, и в `menu` кладётся
**сам экземпляр**, без обёртки:

```js
// Pielet: кольцо, чьим пунктом открывается это меню.
const ring = new Pielet({
  interactionMode: 'hold',
  button: 'right',
  items: [{ typeContent: 'text', content: '☰', isSubMenu: true, menu: someMyContext }],
});
```

```js
// MyContext: то, что кладётся в пункт.
const someMyContext = new MyContext(items, {
  label: 'Photo actions',
  destroyOnClose: true,
  pressAndHold: 'right',
});
```

Метод вызывает `open({ x, y }, { armed: true, dismissible: true })`, и отличие от
`open()` одно — в жесте:

- **Жест удержания вооружается на показе.** Кнопку держит вызывающий код, то есть
  меню, в сабменю которого мы попали: нажатия по нашему контейнеру у нас не было, и
  разбирать отпускание больше некому. Отпускание этой кнопки закрывает меню, а если
  в этот момент под курсором доступный пункт — ещё и исполняет его действие.
  Требует `pressAndHold`, отличного от `'none'`; при `'none'` бросает `TypeError`,
  и в сообщении называет `options.armed` — опцию, которую метод передаёт от вашего
  имени.
- **Правила закрытия поднимаются на время показа.** Без них у непривязанного меню
  их нет вовсе, а прокрутка и `resize` во время удержания закрывают меню-владельца —
  и оставленное висеть сабменю было бы уже ничем не управляемо. Вместе с ними
  начинает работать и `autoHideDistance`.

Показ не отличается ничем, кроме перевода сигнатуры: фокус, подменю, клавиатура и
те же правила. Вызывается каждый раз, когда владелец зовёт показать сабменю, —
а Pielet зовёт это и по наведению с задержкой, и по отпусканию над сектором.

Что стоит знать:

- **Повторный вызов идёт обычным циклом `open()`:** уровни гаснут на месте, корневой
  показывается в новой точке через `animationDuration`. Меню, которое открывают на
  каждый сектор удержания, перерисовывается на каждом переходе — это цена показа из
  чужого кода, а не особенность метода.
- **Действие пункта не должно звать меню обратно.** Отпускание закрывает меню раньше,
  чем зовёт действие, а с [`destroyOnClose`](#destroyonclose) — ещё и разбирает
  экземпляр. `open()` или `close()` изнутри `action` на этом пути бросят `Error`.
  Путь клика ограничения не имеет: там действие исполняется до закрытия.
- **Пресет неотключаем.** Нужно иное — берите `open()` и разводите жест удержания
  сами: например, отпускание должно только закрывать, без действия под курсором.

### `close()`

Закрывает всю цепочку уровней от глубоких к корню, отменяет отложенные открытия и
возвращает фокус привязанному контейнеру. Без привязки фокус возвращать некуда, и
вызов просто скрывает. Повторный вызов безопасен. Бросает `Error`, если экземпляр
уничтожен.

У экземпляра с [`destroyOnClose`](#destroyonclose) этот вызов — и любое другое
закрытие — разбирает его целиком, так что следующий вызов `close()` бросит `Error`.

### `destroy()`

Снимает все подписки и висящие задачи, удаляет все уровни из DOM и очищает
внутреннее состояние.

**`destroy()` идемпотентен, а остальные методы после него бросают `Error`.**
Повторный вызов `destroy()` — обычное дело при размонтировании, и ошибка в нём
была бы ошибкой вызывающего кода. `attach`, `detach`, `open`, `openAsSubmenu`,
`close` после `destroy()` бросают `Error` с сообщением
`MyContext: экземпляр уничтожен`: ими больше нечего делать, и молчаливое отсутствие
эффекта хуже явной ошибки.

Меню, заведённое на один показ, звать это вручную не нужно: у него есть
[`destroyOnClose`](#destroyonclose), и закрытие разбирает его само.

### `MyContext.closeAll()`

Статический метод. Закрывает меню **всех живых экземпляров** на странице — цепочки
уровней от глубоких к корню, отложенные открытия и отложенный показ переоткрытия.
Для приложения, у которого нет ссылок на экземпляры: смена маршрута, открытое
модальное окно, `Escape` на документе.

```js
document.addEventListener('routechange', () => {
  MyContext.closeAll();
});
```

Что важно знать о контракте:

- **Экземпляры не разрушаются.** `closeAll()` закрывает, а не уничтожает: `attach()`,
  `open()` и `destroy()` работают после него как прежде. Единственное исключение —
  [`destroyOnClose`](#destroyonclose): там разбор объявлен частью закрытия, и
  `closeAll()` разбирает такой экземпляр наравне со всеми.
- **Фокус не возвращается.** У каждого экземпляра свой контейнер, и при нескольких
  меню на странице контейнеры конкурируют — выиграл бы тот, что попался последним, а не
  тот, на котором фокус был до вызова. Фокус остаётся там, где его оставил
  пользователь. Это путь внешнего события, каким является и клик по странице.
- **Отложенный показ переоткрытия снимается.** Окно между сокрытием и показом в новой
  точке — это ещё открытое меню, и пережившее вызов оно воскресло бы после того, как
  всё остальное уже закрыто.
- **Уничтоженные экземпляры не трогаются.** `destroy()` убирает экземпляр из реестра
  живых, поэтому противоречия с правилом «после `destroy()` остальные методы бросают
  `Error`» не возникает: вызов не бросает ничего.
- **Возвращаемого значения нет.** Метод — команда, а не запрос.

Реестр живых экземпляров — сильные ссылки, и они не держат на странице ничего лишнего:
экземпляр, о котором забыли `destroy()`, удерживает слушатели и узлы `<body>` и без
реестра, а `destroy()` — обязательный шаг демонтажа, а не необязательная уборка. Для
экземпляра, который демонтировать некому, шаг этот делает
[`destroyOnClose`](#destroyonclose) сам.

с `--vc-item-height`, `--vc-icon-size`, `--vc-chevron-size`, `--vc-radius` и

тесты, как зеркала токенов. `options.animationDuration` переопределяет
`--vc-animation-duration` инлайном на каждом уровне, а инлайн перебивает любую вашу
таблицу стилей.

## Поддержка тем и `prefers-reduced-motion`

Тема задаётся опцией `theme` и попадает в атрибут `data-vc-theme` на каждом
уровне. `auto` оставляет выбор за системной схемой, `light` и `dark` переопределяют
её. Логика выбора палитры целиком в CSS, а модуль только ставит атрибут, поэтому
любой токен переопределяется вашей таблицей стилей и без пересоздания меню. Сменить
же `theme` на живом экземпляре нельзя: атрибут пишется при создании уровня, и
метода смены темы у экземпляра нет.

Тёмная палитра: `--vc-bg-solid` `#1b1d21`, `--vc-text` `#e8eaed`, `--vc-muted`
`#9aa1ab`, `--vc-bg` — 76% подложки против 72% в светлой, `--vc-hover-bg` — 10% текста,
`--vc-separator` — 16% текста,
`--vc-shadow` — `0 8px 28px rgba(0, 0, 0, 0.55)`. Наведение здесь плотнее
(10 % против 6 %): на тёмной подложке та же доля невидимого текста не дала бы строке
признака, а наведение — единственный его носитель.

Медиазапрос темы ограничен `[data-vc-theme="auto"]`: без этого ограничения системная
тёмная схема красила бы и явно светлое меню.

`prefers-reduced-motion: reduce` отключает движение полностью, а не укорачивает
его:

- выключаются переходы как класс свойств — на самом меню и на всех его потомках,
  поэтому шеврон и подсветка пунктов не двигаются тоже. Длительность при этом
  обнуляется правилом медиазапроса, но перебивается инлайновым значением, которое
  ставит уровень, и потому работает именно выключение переходов, а не нулевая
  длительность;
- `transform` у самого меню снимается (поворот шеврона на 180° при развороте
  подменю влево — это признак положения, а не анимация, и он переживает `reduce`);
- отложенный `hidePopover()` не ставится вовсе: под `reduce` в CSS стоит
  `transition: none`, и `display` меняется мгновенно, так что отложенное закрытие
  погасило бы уровень мгновенно — то есть состояние, ради которого отложенность и
  существует, стало бы недостижимым;
- отметка закрытия `data-vc-closing` при этом ставится. Под `reduce` ей анимировать
  нечего, но она снимает события с закрытого уровня, а это нужно всегда: авторское
  правило `display` у меню перебивает UA-правило
  `[popover]:not(:popover-open) { display: none }` по происхождению, и без отметки
  закрытый уровень остался бы отрисованным и принимающим события — невидимое меню,
  глотающее клики там, где его уже нет.

Меню под `reduce` видно сразу после открытия, без ожидания кадра.

## Ограничения иконок

Иконка типа `svg` — это **недоверенная разметка**: она приходит от автора пункта, и
подставляется в DOM как есть, поэтому очищается по белым спискам элементов и
атрибутов, а не по набору запретов. Всё, чего в списках нет, удаляется: элемент
вместе с поддеревом, атрибут у каждого уцелевшего элемента. Из прочих узлов
остаются только текст и CDATA. Корневому `svg` принудительно выставляются
`width="100%"`, `height="100%"`, `aria-hidden="true"`, `focusable="false"`,
`overflow="hidden"` и канонический `xmlns`.

Это значит следующее, и лучше знать заранее, чем узнавать об этом на своей странице.

**Иконку нужно инлайнить.** Разметка `type: 'svg'` — это строка в вашем коде, а не
адрес. Внешний спрайт-лист через `use` не работает: ссылки `href` и `xlink:href`
допускаются только фрагментные, то есть `href="#имя"`. Всё остальное — включая
относительный путь, который на любом другом origin уже внешний — вырезается. Внешний
спрайт, отданный с того же origin, тоже вырежется: правило не смотрит на адрес, а
смотрит на форму.

**Презентация задаётся presentation-атрибутами и CSS библиотеки.** Атрибут `style`
вырезается целиком, поэтому задать цвет, прозрачность или позиционирование через
него нельзя. Пишите `fill="currentColor"`, `stroke-width="1.5"` и подобное прямо в
разметке, а мелкие правки делайте селектором по слоту: `.vc-icon-slot > *`
описывает любого ребёнка слота, потому что сам svg-узел класса не получает
намеренно — класс был бы мостом из недоверенной разметки в стили страницы.

**CSS-escape-последовательности вида `\75 rl(...)` санитизация не ловит.** Проверка
значений presentation-атрибутов ищет `url(` как подстроку и убирает атрибут, если
после удаления внутренних `url(#имя)` осталась посторонняя ссылка; escape-последовательность
разбирается уже движком CSS, и до него проверка не доходит. **Это осознанный остаток,
а не недосмотр:** закрыть его можно только разбором CSS — то есть зависимостью или
большим самописным парсером, и цена несоразмерна выгоде. Если иконки приходят из
недоверенного источника, ответ уровня платформы один: задайте CSP владельца
страницы — например, `default-src 'self'` без `'unsafe-inline'` — и держите иконки на
своём origin. Санитизация уменьшает поверхность атаки, но не заменяет CSP.

**Легаси-псевдонимы SVG 1.1 в camelCase вырезаются:** `strokeWidth`, `fillOpacity`,
`clipRule`, `stopColor`, `textAnchor`, `fontSize`, `fontFamily`, `letterSpacing`.
Причина в том, что разбор регистрозависим, а список атрибутов точен: `localName`
разобранного XML сохраняет регистр, и `strokeWidth` — уже не то же самое, что
`stroke-width`. Старый экспорт из Illustrator или Inkscape может отрендериться
неверно по толщине обводки, по наклону заливки или по якорю текста. **Симптом
молчаливый:** ничего не падает и не логируется, иконка просто выглядит не так.
Проверяйте такие файлы глазами; надёжнее — прогнать их через редактор, который
переписывает атрибуты в kebab-case.

**Атрибут `id` внутри иконки сохраняется**, и это сделано намеренно: без него `use`
и градиенты не ссылались бы сами на себя. Плата в том, что после вставки
`use href="#id"` ищет элемент во всём документе, то есть на странице-хозяине.
Идентификаторы, которые генерирует сама библиотека, начинаются с префикса `vc-`
(`vc-1-0`, `vc-1-0-sub-1`), чтобы не совпасть с чужими; **не используйте префикс
`vc-` в собственных иконках**. Свои `id` внутри иконок делайте уникальными на всю
страницу, а не только внутри иконки.

**Иконка, чей `viewBox` обрезает содержимое намеренно, будет обрезана.** Корню
принудительно выставляется `overflow="hidden"`, и это не украшение: авторский
`overflow` — presentation-атрибут, то есть источник автора, и он перебивает правило
UA-стилей, вьюпорт иконки перестаёт обрезать содержимое, а вместе с
`pointer-events` это оверлей, перехватывающий клики по меню. Ровно тот же результат
давал `style`, но без него. Если иконке нужно, чтобы содержимое выходило за
`viewBox`, отдайте это не иконкой, а отдельным элементом рядом.

**`display` и `visibility` не принуждаются.** Они разрешены, и потому
`display="none"` в вашей разметке отрисует иконку в никуда — молча, как и
`overflow` до принудительной установки. Уберите атрибут, если он не нужен.

**`filter`, `marker-*`, `pattern*`, `color-interpolation-filters` и текстовые
атрибуты разрешены, хотя соответствующие элементы в белый список не входят.**
Позиция защитная, на случай расширения списка элементов: атрибут, ссылающийся на
`filter` или на `pattern`, не должен ломаться о белый список, когда элемент туда
добавится. **Читать белый список атрибутов как обещание отрисовки нельзя** — сейчас
`filter`, `marker`, `pattern`, `text` и `tspan` в белый список элементов не входят и
вырезаются вместе с поддеревом, так что разрешённый `filter="url(#f)"` ссылается в
ничто.

### Иконки `emoji` и `raster`

`{ type: 'emoji', value: '📄' }` — символ в `span.vc-icon`, помеченный `aria-hidden`,
чтобы не дублировать озвучку лейбла.

`{ type: 'raster', value, alt }` — `img` с обязательным непустым `alt`. Принимаются
только `http:`, `https:` и `data:image/…`; остальные схемы отбрасываются, и
элемент остаётся без `src`. `alt` обязателен по контракту: пустой или
отсутствующий превращает картинку в недоступную метку.

Описание иконки предъявляет `iconAction`, и проверяется оно на показе: `open()`
бросает `TypeError` с путём вида `vc-3-0:2.iconAction.alt`, если `alt` пуст,
`value` пуст, тип не из трёх или само описание не объект. До показа иконки не
существует, и проверять её в конструкторе не на чем.

## Запуск тестов

```bash
npm test              # весь набор: unit, chromium, firefox, webkit
npm run test:unit     # только юнит-тесты, без браузера
npm run test:e2e      # только браузерные, на трёх движках
npm run typecheck     # tsc --noEmit по src/, Demo/, scripts/ и tests/
```

Проверить, что рантайм-зависимостей нет, можно одной строкой:

```bash
node -e "const p=require('./package.json'); if (p.dependencies) { console.error('dependencies не должны существовать'); process.exit(1); } console.log('ok')"
```

В `playwright.config.js` один воркер: Firefox в параллельном режиме роняет
программный композитор, и падал бы сам движок, а не код.

Типовое окружение проверяется двумя программами подряд, и порядок обязателен:
сначала браузерная (`"types": []`, `src/**` и `Demo/**`), и только потом
node-программа (`"types": ["node"]`, `scripts/**` и `tests/**`). Node-глобал в
`src/**` или `Demo/**` ломает `npm run typecheck` именно этим порядком;
изолированный `tsc -p tsconfig.node.json` его не увидит, потому что юнит-тесты
тянут `src/**` в node-типизацию.

## Демо

```bash
npm run serve
```

Демо отдаётся на `http://127.0.0.1:4173/` (порт меняется переменной `PORT`).
Страница показывает семь сценариев: базовое меню, вложенность, отключённые
пункты, иконки всех трёх видов, длинный список, автоскрытие и всё вместе. Правый
клик по любому блоку сценария открывает его меню; переключатель в шапке меняет
тему страницы.

Блок «Автоскрытие» — единственный, у кого задан `autoHideDistance`, и он же
единственный, чьё меню живёт не всегда: уведя курсор за пределы порога, вы
прячете меню, и никакого «безопасного поля» вокруг него нет. Подменю в нём
длиннее корня намеренно — иначе не существовало бы точки, которая далеко от
корня, но близко к подменю, то есть самого случая, ради которого порог и задан.
